# 2026-09-06 サービス参加者の操作権限・生成エラー監査

## 結果

#469反映後のmain（68565351）を起点に確認した。主要なサービス向け投稿フローで、本人所有の分身への書き込みをWorkspaceのOWNER/ADMINだけに限定する追加の判定は見つからなかった。

一般向けDailyMissionSectionには、409を一律に「作成中か作成済み」と表示する問題が残っていた。方針未承認などの409も同じ文言になり、通信例外はfinallyのみで画面に出なかった。サービス側と共通の応答処理・UUID互換処理を使い、公開エラーと受付番号を表示するよう修正した。

## 確認範囲

| 対象                                                     | 確認内容                                                                                  |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| サービス向け分身・SNS・テーマ・方針・週間予定・投稿案API | Service SlugからWorkspace/Groupを固定し、認証Userを使用する                               |
| SNS・テーマ・方針・週間予定・投稿案Repository            | 本人所有とcanManageBunshinによる判定、Group・Workspace一致、有効な所属を維持する          |
| 採用・活動・投稿記録Repository                           | 同じサービス・本人所有の分身と対象Missionを確認する                                       |
| 週間予定・投稿案生成サービス                             | 読み込みから保存までサービスのgroupIdを引き継ぐ                                           |
| 商品プロフィール・本人URL登録API                         | Service/Userをサーバー側で固定する。URL有効化は管理操作として分離する                     |
| OWNER/ADMIN固定判定の残存箇所                            | Workspace設定・運営管理用、または本人所有とのOR条件であり、今回の参加者保存拒否と区別する |
| 一般向け投稿案UI                                         | 409の誤表示と通信エラー非表示を修正する                                                   |

## 回帰テスト

既存の実DBテストを拡張し、サービス内MEMBER本人が、方針保存・承認に続いてテーマ作成、週間予定生成・確定、投稿案保存・一覧表示、採用、手動投稿記録まで進めることを検証する。同じ日の重複作成はCONFLICTを維持する。

他人（Workspace ADMINを含む）、別Workspace、別Group、Group未指定に対して、方針保存・承認、週間予定確定、投稿案一覧、投稿記録を拒否することを検証する。

## 限界

本監査は上記のコード経路と自動テストを対象とする。全機能・全端末での不具合不存在を保証しない。本番の利用者操作やAI生成は今回実行していない。既存の設定・本番データ・利用者の変更は変更していない。
