# ポイント・バッジ利用者導線 実装報告

## 1. 調査した内容

ポイントの残高・履歴・失効予定と、バッジの獲得済み・進捗・おすすめ画面は実装済みだった。一方、サービスホームから詳細画面へ直接進む入口がなく、活動画面ではポイントと画像作成回数が同じ欄に表示されていた。また、試験対象外の利用者にもポイントとバッジの欄が表示される状態だった。

## 2. 変更したファイル

- `apps/web/app/s/[serviceSlug]/home/page.tsx`

## 3. 主要な設計判断

- サービスと参加者の両方に有効な`REWARDS.POINTS_BADGES`設定がある場合だけ、利用者向け入口とポイント・バッジ情報を表示する。
- サービスホームから「ポイント・バッジを見る」を1回押せば、残高と獲得数を確認できる位置へ移動する。
- 利用者へ示す操作を「投稿案を開く」「投稿後に記録する」「通常1分ほど待って開き直す」の3つに限定する。
- ポイントの詳細画面とバッジの詳細画面を相互に移動できるようにし、現在のサービスが属するWorkspaceをURLへ固定する。
- ポイントと画像作成回数を別の欄に分け、異なる残高を同じ特典として誤認しにくくする。

## 4. 実行した検証

- 利用対象者だけに入口と情報を表示する境界テスト
- サービスホーム、活動、ヘルプ、ポイント、バッジ間の導線テスト
- Webの型検査、lint、build

## 5. 未解決事項

- 本番iPhoneで、サービスホームから活動画面、ポイント履歴、バッジ進捗へ順に移動できることを確認する。
- 実際の行動から反映までの時間が継続して1分を超える場合は、管理者の自動反映画面で処理状況を確認する。

## 6. 次Phaseへ進める条件

- 対象利用者にはポイント・バッジ入口が表示され、対象外利用者には表示されない。
- 投稿案の初回確認または投稿記録後、活動画面とポイント履歴へ同じ結果が反映される。
