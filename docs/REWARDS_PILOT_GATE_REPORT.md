# ポイント・バッジ30人限定試験

更新日: 2026-09-11

## 調査した内容

- グループ機能には、システム管理者によるグループ許可と、運営者による参加者別許可がすでにある。
- ポイント付与、共通バッジ判定、利用者画面、利用者APIはこの許可を確認していなかった。
- このままでは対象者を限定した4週間の試験運用ができなかった。

## 変更した内容

- `REWARDS.POINTS_BADGES` を管理可能な機能として追加した。
- グループ許可と参加者別許可の両方が有効な場合だけ、ポイントとバッジを付与する。
- 対象外期間の行動を処理済みにして、再開後の遡及付与を防ぐ。
- 対象外の利用者には試験利用中であることを表示し、利用者APIも拒否する。
- 1グループで有効にできる参加者を30人までに制限した。
- 運営画面に現在の人数と対象者設定への導線を追加した。

## 運用手順

1. システム管理者が対象サービスの「ポイント・バッジ（試験利用）」を許可し、開始・終了日時を設定する。
2. サービスのポイント設定画面から「試験利用者を選ぶ」を開く。
3. 対象参加者を選び、「この参加者に利用を許可する」を押す。
4. 対象者のポイント・バッジ画面と実際の付与を確認する。
5. 問題があれば参加者別停止、または既存のポイント一括停止を使う。

## 検証

- グループと参加者の二重許可、期間、同意済み参加状態を確認する単体テスト
- 30人上限とmigrationの境界テスト
- ポイント・バッジ処理の対象外完了テスト
- 利用者画面とAPIの対象者限定テスト
- Prisma schema検証、database/webの型検査とlint

## 残る運用確認

- 本番で対象サービスと最初の参加者を許可する。
- 対象者と対象外者の両方で画面および付与結果を確認する。
- 4週間、投稿完了率、継続率、交換率、原価、不正率を記録する。
