# マルチサービス参加フロー Web/API 実装報告

## 対象

MS-1D-Bとして、サービス専用入口から参加申請までを接続した。

## 実装内容

- `/s/{serviceSlug}`でログイン状態と現在の参加状態を確認
- 公開済みのサービス別利用規約・プライバシーポリシーを最新版だけ表示
- 文書ごとの明示同意後に参加申請
- 公開登録は即時参加、承認制は承認待ちとして表示
- 参加済み・承認待ちを再申請させない表示
- サービスslugから参加するAPI
- 同一サービスの有効な管理者だけが使える承認API

## セキュリティ境界

- クライアントからworkspace ID・service ID・参加者IDを指定して参加できない
- 参加APIはslugをサーバー側で解決する
- 承認APIはworkspace・service・membershipの一致をDBで再検証する
- 参加・承認ともverified sessionとSame-Origin検証を必須とする
- 最新版の法務文書IDと提出された同意IDが一致しない申請は拒否する
