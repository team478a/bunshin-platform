# トレンド調査Provider比較計画

## ゴール

Grok、Exa、Firecrawlを同じ日本語queryで比較し、X上の兆候、Web全体の裏付け、費用を分けて判断できるようにする。点数だけで本番Providerを自動変更しない。

## 比較ケース

実キーの準備後、DEVELOPMENT環境で最低限次を同じ日時に実行する。

1. Xで24〜72時間以内に増えている日本語の短尺動画企画
2. X以外の一次情報でも裏付けられる話題
3. 古い話題が検索上位に残りやすい曖昧なテーマ
4. 根拠が少なく「予測不能」と判断すべきテーマ
5. 個人情報や非公開Knowledgeをqueryへ含めない境界ケース

queryには利用者名、LINE user ID、メールアドレス、Knowledge本文、Memory本文を含めない。

## 評価指標

| 指標     | 重み | 判定方法                                 |
| -------- | ---: | ---------------------------------------- |
| 関連性   |  30% | 人間が0〜5で採点                         |
| 出典品質 |  25% | 人間が0〜5で採点                         |
| 根拠充足 |  15% | HTTPSの引用件数／要求件数                |
| 鮮度確認 |  15% | 公開日時を確認でき、指定期間内だった割合 |
| 安定性   |  10% | 全ケースに対する成功率                   |
| 費用効率 |   5% | 同一比較内の相対原価                     |

出典に公開日時がない場合、鮮度は推測せず0点とする。X Searchの引用だけで公開日時を取得できない場合は、追加取得の費用と必要性を別に評価する。

## 採用候補の最低条件

- 全比較ケースを実行済み
- Providerエラーが0件
- 関連性70点以上
- 出典品質70点以上
- 根拠充足60点以上
- 安全でないURL、秘密情報、越境データが0件

最低条件を満たすProviderが複数なら自動推薦しない。X向け調査はGrok、Web裏付けはExa／Firecrawlという併用も認める。

## 実装したもの

- Provider別観測値の純粋な評価関数
- 指標別、総合点、原価、時間を含むMarkdownレポート生成
- 先に固定したケースIDに対する不足、未知ケース、失敗、重複、採点範囲外の拒否
- 単独候補だけを提示し、同点・複数候補では人間レビューを要求する停止条件

## 今回実施しないこと

- 外部APIの実行
- APIキーの登録
- 本番Providerの決定
- 日次JobやMission生成への接続
- 点数による設定の自動有効化

実測後は結果を新しい報告文書へ固定し、Provider採否をDecision Logへ記録してから配信経路を変更する。
