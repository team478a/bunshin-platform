# ADR: マナベルスタイルは生成AIの進化を取り込む

- 状態: Proposed（PR-0 Draft PRで田中の確認待ち）
- 決定者: 田中（サービス責任者）
- 方針決定日: 2026-10-16
- 文書化: 2026-10-17
- 対象: マナベルスタイルの動的AI研修
- 関連: [動的学習本線化指示書 v3](MANABERU_PRODUCTION_LEARNING_FLOW_GAP_REPORT.md)、`docs/DECISION_LOG.md`

## 背景と判断

生成AIの性能やツールが急速に進化するなか、モデルの回答性能や特定ツールの操作手順そのものをサービスの独自価値にすると、同等機能がモデル本体へ取り込まれた際に価値が失われる。マナベルスタイルの価値はAIの代行ではなく、本人が最新のAIを自身の仕事・生活で使えるようになることに置く。

したがって、固定教材・特定モデル・特定ツールの機能に依存せず、本人の希望から始まる動的な学習経路を本線とする。AIが持つ機能はProvider境界の内側で利用し、マナベルは本人の記録、学習の進行、安全、継続支援を担う。本ADRは設計方針の記録であり、実装・本番公開・学習効果の確認を意味しない。

## 設計原則

1. **価値は本人の上達に置く。** 本人の上達、個別化、新しいAI機能の本人向けの翻訳、継続、本人が管理できる学習記録を価値とする。AIによる成果物の代作、手順・プロンプトの暗記、特定ツールの特定版に固定された教材を価値の中心にしない。
2. **モデル・Provider・能力を固定しない。** 提案、追加質問、相談、提出レビュー、次の実践、LINE会話を用途別Portで扱い、モデルとProviderを差し替え可能にする。画像、長文脈、構造化出力、検索、音声、ツール操作等は能力として表し、モデル名による機能分岐を避ける。実際のProvider抽象化はPR-Hの範囲。
3. **AIの能力を再実装せず、流れと安全を持つ。** 外部AIの新能力は境界越しに利用する。マナベルが維持するものは、本人の記録、学習段階の制御、安全（同意・受講枠・費用上限・停止・分離・監査）、LINEでの伴走に限る。モデルの自由な応答に段階遷移を委ねず、サーバー側で許可された進行を制御する。
4. **手本のあとに本人の一歩を残す。** 手本や下書きを提示してもよいが、その後は本人が試す具体的な行動を必ず促す。これはモデルが変わっても維持し、評価セットで確認する。
5. **学習記録は本人が管理し、モデルに依存させない。** 記録は特定モデルの出力形式に依存しない構造データとし、本人が確認・修正・エクスポート・削除できるようにする。テーマ横断の本人像は同一本人のマナベル内に限り、他サービス、Workspace、Bunshin Memoryと共有しない。AIの推測は根拠とともに「未確認」とし、本人の確認前に確定事実として扱わない。
6. **モデル変更は評価してから行う。** PR-Eで作る多様な希望20件以上の評価セットと、PR-Gのマナベル独自評価手順を比較基準にする。能動的学習、情報量、個別化、答えの渡しすぎ、誤り・画面推測、範囲外対応、費用・応答時間を評価し、人間の承認後にモデル設定を切り替える。1日以内に比較結果を得られる状態は目標であり、現状の保証ではない。
7. **AIツールの進化を練習テーマへ翻訳する。** 受講者が使うAIツールの新機能は出典付きで収集し、「本人の仕事でどう役立つか」を練習テーマとして提案する。運営者が確認・承認するまでは提案に使わない。既存TrendResearchProviderPort等の再利用可否はPR-Iで先に調べる。
8. **研究は設計の参考であり、効果保証ではない。** 下記の研究は対象、教材、地域、期間、モデルが限定される。結果をマナベル受講者の効果として説明・広告しない。マナベル自身の品質はPR-G評価と実受講者の記録で検証し、その評価結果も学習効果の因果的保証とは区別する。

## 段階導入との関係

- 本線化の実装順は **PR-0 → A → B → C → D → E → F → G → H → I**。PR-0〜Gは動的経路の本線化と公開判定、HはProvider抽象化・モデル比較、Iはツール新機能の練習テーマ化。
- 各PRはDraft PR＋実装報告を提出し、田中の確認後に次へ進む。PRのマージ、本番release、migration、環境設定、Pilot開始は別の状態・承認とする。
- 内部テスターはA/B後に基本経路から段階公開し、C〜Fは各PRの完成・確認・本番反映後に追加する。外部初回公開はA〜G、通し評価の田中承認、自動削除の本番稼働を含む全条件がそろうまで行わない。
- Phase 1完了とPhase 2以降への移行承認は別ゲートである。PR #1の正式レビュー記録が確認できていないため、PR-0で事実を報告し、田中の明示承認を得るまでPR-Aには着手しない。

## 個人データ・運営者閲覧の関連決定

2026-10-17のサービス責任者決定記録に基づき、動的経路で新たに保存する会話・提出物・画像・LINE本文と画像は作成から90日、希望・環境は受講終了後90日、構造化された学習要約・本人像は受講終了後1年を保持の設計基準とする。既存の `TRAINING_RETENTION_V1` を拡張し、別の期限ロジックを作らない。これはサポート案件の90日削除とは別の判断である。

本人はデータを確認・修正・エクスポート・削除できる設計とする。運営者画面は件数・状態・最終利用日時・テーマ数・現在段階・エラー有無・費用集計に限り、会話等の本文は通常閲覧できない。本人がサポートを求めて明示共有した会話だけを例外とし、共有を取り消せるようにする。自動削除をProductionで有効化すること自体は別途承認・動作確認を要する。

## 未決事項・見直し条件

別Providerの選定、モデル能力表、評価担当者・比較実行の承認方法、新機能情報の承認担当、費用上限、テーマ数、LINE Push月間上限、範囲外依頼の最終リスト、削除cronのProduction有効化は、このADRで確定していない。各PRで提案・承認を得る。

評価結果、Provider仕様、受講者の使い方、個人情報保護要件に重要な変化があれば、このADRとDecision Logを見直し、過去の判断を暗黙に上書きしない。
