# マナベルスタイル PR-5 操作教材の再検証

[設計判断](../adr/MANABERU_BROWSER_RECHECK_PR5.md) · [開発環境の準備](./MANABERU_BROWSER_INTEGRATION_PR4.md)

- 対象は既存の開発用メモプレビュー教材。教材画面の「教材と画面が違う」で、現在閲覧中の版を既存ワーカーへ渡す。重複報告は同じ版で1時間に1ジョブへまとめる。画面画像を添えた既存の実践相談では、利用者と既存の AI 回答の両方が環境差を示す場合に、教材の再検証を依頼する。画像や相談内容はワーカーへ渡さない。
- 定期実行では最終検証から7日を過ぎた現行版を対象にする。教材生成時の依頼者と現在の学習要望から認可を再確認する。該当する受講資格が失効している場合は別の有効な受講者から報告できる。
- Playwright で全手順と成功条件を再確認する。標準のプレビューボタンが見つからず、既知の簡易プレビューを一意に識別できる場合は、そのステップだけ候補を切り替える。成功した同一内容は最終検証日時を更新し、操作内容が変わった場合は画像付きの新版を保存する。操作失敗時は前の教材を継続表示する。
- 旧版は保持する。該当サービスの所有者が現行版 ID を指定して復旧すると、旧版の説明・画像を復旧版として保存し、既存の Program 操作ログに記録する。

開発用 DB に新しい migration を適用し、Web とワーカーに `APP_ENV=development` を設定する。定期ジョブは既存の運用スケジューラから下記コマンドを毎日呼ぶ。キューの処理には既存の `serve` または `once` を使う。

```sh
pnpm --filter @bunshin/browser-worker start schedule-training-rechecks
pnpm --filter @bunshin/browser-worker start rollback-training-material "$WORKSPACE_ID" "$ACTOR_ID" "$OLD_MATERIAL_ID" "$CURRENT_MATERIAL_ID"
```

既存の Playwright 1.65.1 と Sharp 0.35.4（いずれも Apache-2.0）を使用する。再検証時の AI 呼び出しは0回。公式更新情報・評価スコアからの再検証や外部サービスの操作探索は今後の対象。実践相談の実 AI 呼び出しは既存の原価管理を使用する。

## 開発検証

Chromium 159.0.8154.6 で同一画面の再実行、承認済み候補への切り替え、候補が両方使えない場合の操作失敗を確認した。変更後の実行は約1.29秒で、4手順から WebP 11枚を生成した。
