# AI研修 管理画面の受講期間表示 実装報告

## 調査

main `4ccb5516`（#1001）を基準とした。受講者向け画面と学習操作は受講期間を確認するが、管理画面は登録状態ACTIVEだけで受講中/継続率を集計し、Lifecycle欄も「受講中」と表示していた。管理画面・集計・操作カード、既存認可/Privacy/状態変更テストと公開入口を確認した。

## 変更したファイル

- web/services/ai-training-enrollment-display: Provider/DBに依存しない表示射影。登録状態を変更せず、開始日時以下・終了日時未満で判定する。
- web/services/ai-training-admin-dashboard: 期間内ACTIVEだけを受講中/継続率/声かけ対象にする。期限終了/状態未更新/開始前/開始日時未確定を集計し、過去の課題・成果・実務利用集計は維持する。
- manage/training/pageとtraining-admin-dashboard: startsAt取得、1回のサーバー確認時刻、件数/確認時刻/集計対象の説明、期間表示変更時の操作カード再マウント。
- training-lifecycle-card: 利用状況と登録状態、予定開始/終了日時と確定終了日時の区別。状態未更新の場合の説明と、元の登録状態による確認操作を維持。
- 関連Unit/実Page構成/SSR/操作テスト、D-140、ロードマップ、本報告。

## 設計判断

ACTIVEのまま期限を過ぎた場合は「期限終了（状態未更新）」と表示する。終了日時なしは上限なし、開始日時なしは開始未確定、開始前は別状態とする。登録済みの招待/終了/取消/期限終了は予定期間より優先する。

集計とLifecycleカードは同じサーバー確認時刻で表示判定する。Client側の現在時刻で判定し直さず、確認時刻と画面更新を案内する。受講状態のCASへ表示状態を代入しない。理由・確認・UUID・updatedAtによる既存の管理者操作を維持し、期限後ACTIVEを画面閲覧だけで終了させない。

予定終了日からACTIVEの確定終了日・保持期限起算日を補完しない。既存のEXPIREDの終了予定日Fallbackも過去/現在の日時だけとする。状態未更新への終了/取消は別の明示的操作であり、契約延長・自動再開・返金・削除を意味しない。
