# ポイント・バッジ無料試験 開始導線レポート

## 1. 調査した内容

- 30人上限、4週間の期間、対象者別の利用可否、開始前確認、途中集計、終了後CSVは実装済みだった。
- 運営者は参加者を1人ずつ開いて設定する必要があり、最大30人をスマートフォンで準備する負担が大きかった。
- 試験期間はシステム管理画面で開始日時と終了日時を個別入力する必要があった。
- 利用規約への同意が終わっていない人も、管理画面の試験利用者数へ含まれる場合があった。

## 2. 変更したファイル

- `packages/database/src/rewards-pilot-access.ts`: 同意済み参加者1〜30人で試験対象を一括置換する処理を追加した。
- `packages/database/src/index.ts`: 一括設定処理をWebから利用できるよう公開した。
- `apps/web/app/s/[serviceSlug]/manage/points/page.tsx`: 今日から4週間の設定と、参加者の一括選択画面を追加した。
- `apps/web/app/styles.css`: スマートフォンで押しやすい参加者チェック欄を追加した。
- `packages/database/test/rewards-pilot-bulk-assignment.test.ts`: 一括入替と同意境界を検証した。
- `apps/web/test/rewards-pilot-boundary.test.ts`: 管理画面の開始導線を検証した。

## 3. 主要な設計判断

- システム管理者は「今日から4週間に設定する」を押すだけで、開始日時と終了日時を設定できる。
- サービス運営者は同意済み参加者をチェックし、選んだ人を試験対象として一括保存できる。
- 選択を保存すると、以前選ばれていて今回外した人は停止する。ポイント・バッジの履歴は削除しない。
- 30人上限、サービス境界、運営者権限、参加状態、規約同意をサーバー側で再確認する。
- 既存の期間・上限・監査テーブルを利用するため、新しいMigrationは追加しない。

## 4. 実行した検証

- 古い対象者を先に停止してから、新しく選んだ対象者を有効化できること。
- 対象者の期間がサービスの4週間とそろうこと。
- 同意前、別サービス、停止中の参加者を選べないこと。
- 1人未満または30人超の一括設定を拒否すること。
- 型検査、lint、全体テスト1,170件、production buildをすべて完了した。

## 5. 未解決事項

- 実アカウントの試験開始は、本番へ反映後に運営者が操作する必要がある。
- 期間を再設定すると新しい4週間の集計期間になるため、前回分は先にCSVで保存する。
- 招待、参加、利用規約への同意が完了していない人は一括選択欄へ表示しない。

## 6. 次Phaseへ進める条件

- 本番の「ポイントとバッジ」で4週間を設定する。
- 同意済みのテスト利用者を1〜30人選び、開始確認5項目がすべて準備済みになることを確認する。
- 対象者と対象外者を各1名確認し、ポイント・バッジの表示と付与範囲が分離されている証跡を保存する。
