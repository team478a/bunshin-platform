# ポイントの使い道 利用者画面 実装報告

## 1. 調査した内容

- 有効期間と版を管理するポイント交換カタログ
- 別の投稿案と投稿画像のポイント交換処理
- 試験利用者本人に限定したポイント画面
- サービス内の投稿パートナー画面と画像作成画面への導線

## 2. 変更したファイル

- `apps/web/app/(app)/points/page.tsx`: 使い道、必要WP、残高状態、利用先を表示
- `apps/web/src/rewards/point-use-options.ts`: 有効な利用先を持つ交換メニューだけを組み立てる処理
- `apps/web/app/styles.css`: スマートフォン向け交換メニュー表示
- `apps/web/test/point-use-options.test.ts`: 利用先と不足WPの判定
- `apps/web/test/rewards-member-guide.test.ts`: 利用者向け説明と機能判定の境界

## 3. 主要な設計判断

- 表示する特典名、説明、必要WPは有効な交換カタログを正とし、画面へ固定しない。
- 投稿画像は本人が所属するサービスで画像機能を利用できる場合だけ表示する。
- 別の投稿案は本人所有の投稿パートナーへ直接移動し、未作成なら作成画面へ案内する。
- 残高不足でも利用場所は確認できるようにし、あと何WP必要かを明記する。
- ポイント画面を開いた時点では消費されず、利用先で確認後に交換することを明記する。

## 4. 実行した検証

- 有効な利用先がないカタログ項目を表示しないこと
- 残高以上の特典は利用可能、不足する特典は必要な差額を表示すること
- Webの型検査、Lint、テスト、Production build

## 5. 未解決事項

- 本番のiPhoneで文字量、ボタン位置、各利用先への遷移を確認する。
- 交換カタログ自体を運営者が変更する管理画面は別ゴールとする。

## 6. 次Phaseへ進める条件

- 本番で有効な交換メニューだけが表示されることを確認する。
- 残高が十分な場合と不足する場合の表示、および利用先への遷移を確認する。
