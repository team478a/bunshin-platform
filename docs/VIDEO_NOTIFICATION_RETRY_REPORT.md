# 動画通知の再送対策

## 対象と実装

毎日の字幕動画・個別動画の完成通知と、運営者による動画配布通知に共通する再送対策を追加した。LINEが受け付けた直後の通信切断や、通知状態のDB保存失敗でジョブが再実行される場合を対象とする。

- 完成通知はRender ID、配布通知はDelivery IDを初回からLINEの`X-Line-Retry-Key`に使用する。
- HTTP 409かつ`x-line-accepted-request-id`がある応答のみ受付済みとして成功にする。その他のエラーは成功扱いしない。
- LINE側のキー保持は24時間のため、完成日時または配布作成日時から23時間で通知を停止する。初回送信前に停止した場合も含む保守的な制限で、DBへの初回結果保存前に中断しても期限を延長しない。通知が止まっても完成動画は確認画面に残る。
- 動画ジョブが通知エラーの分類を保持するよう修正し、一般的なインフラエラーへの置き換えを防ぐ。
- 通知設定、受信者の所有範囲、通知停止設定、LINE残枠の既存確認は維持する。DB変更はない。

LINEの受付成功は端末への到達保証ではない。再試行中のチャンネル・受信者・内容変更を固定する永続送信スナップショットは今回追加していないため、設定変更をまたぐ厳密な一度限りの送信は残課題とする。既存通知への後付けキーは、変更前にキーなしで受け付けられた送信を識別できない。

## 検証

通信タイムアウト後に同一キー・同一本文で再試行すること、受付済み応答、未確認409、不正キー、期限到達時の送信停止、送信済み状態のスキップを自動テストする。実際のLINE送信は行わない。

## 残作業

本番CIと限定アカウントでの運用確認後、画像の参考素材入力、動画ファイル直接通知、毎日のAIキャラクター動画を個別の作業として進める。
