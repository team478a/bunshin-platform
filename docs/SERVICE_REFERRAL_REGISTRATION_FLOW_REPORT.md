# 副業向け無料サービス: 紹介URL・登録引き継ぎ

## 実装内容

- `GET /r/{紹介コード}` を追加した。紹介コードが有効な公開サービスだけを解決し、サービス参加ページへ遷移する。
- 遷移時に、個人情報を含まないクリック記録を作成する。流入元、キャンペーン、コンテンツ、表示パターンは上限付きの識別ラベルだけを記録する。
- サービス参加時に、紹介コード・クリックID・サービス・紹介者Membershipの整合性をサーバー側で再確認する。
- 被紹介者のMembershipごとに紹介関係は1件だけ作成する。後から別のURLを開いても、確定済みの紹介者を変更しない。
- 自己紹介、停止済みコード、期限切れクリック、別サービスのクリックは紹介として保存しない。ただし、通常のサービス参加を妨げない。
- LINEログインとメールログインのどちらでも、許可済みの紹介パラメータだけを短時間保持して、ログイン後のサービス参加画面へ戻す。

## URL形式

紹介者が配るURLは次の形式とする。

`/r/FRIEND2026`

任意の計測ラベルは `source`、`campaign`、`content`、`variant` に限定する。外部URL、リダイレクト先、個人情報は受け取らない。

## 安全性

- 紹介コードは全サービスで一意にする。
- URLの遷移先はサーバーが解決した公開サービスだけであり、クライアントはサービスIDや遷移先を指定できない。
- ログイン後に保持できるパラメータは、固定形式の紹介コードとUUID形式のクリックIDだけである。
- 画像クレジットの付与はまだ行わない。次段階の成果判定ジョブで、初期設定完了または初投稿の条件を満たした時だけ、ルールに従って付与する。

## 今回の対象外

- 紹介コードの自動発行画面
- 利用者向けの共有、QRコード、紹介人数・残高画面
- 画像クレジットの消費・返却
- 紹介特典の判定・付与ジョブ
- 現金、換金、多段紹介、不正スコアリング

## 成果判定・クレジット付与

- 被紹介者が初期設定を完了した時、または最初の投稿を報告した時に、同じサービス内の紹介関係を確認する。
- 有効な紹介特典ルールがある場合のみ、紹介者または被紹介者へ画像クレジットを付与する。
- 特典は紹介・ルール版・受益者Membershipの組で一度だけ記録し、残高の更新と台帳を同じトランザクションで保存する。
- 月間上限、特典の有効期限、紹介者の有効Membershipを再確認する。
