# マルチサービス運営管理入口 実装報告

## 目的

サービス運営管理者が内部のGroup IDを意識せず、サービス専用URLから日常管理へ入れるようにする。

## 実装範囲

- `/s/{serviceSlug}/manage/members`: 参加者と利用機能
- `/s/{serviceSlug}/manage/knowledge`: 公式資料・FAQ
- `/s/{serviceSlug}/manage/legal`: 利用規約とプライバシーポリシー
- `/s/{serviceSlug}/manage/badges`: サービス内バッジ
- サービスホームの管理リンクを上記URLへ変更
- 既存画面の戻る導線をサービス名義へ変更

## セキュリティ境界

- ブラウザーからGroup IDを受け取らない。
- `serviceSlug`をサーバー側で解決し、解決済みのサービスIDだけを既存管理画面へ渡す。
- 参加者、公式資料、法務、バッジの既存管理者認可をそのまま再利用する。
- 他サービスの情報をSlugやクエリで指定して取得できない。

## 今回変更しない範囲

既存Server Actionの保存後リダイレクト先は、互換性維持のためGroup URLのままとした。次のMS-2D-Lで、サービス専用入口から実行した操作だけサービス専用URLへ戻すための安全な遷移コンテキストを実装する。
