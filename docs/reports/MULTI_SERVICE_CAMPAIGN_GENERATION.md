# サービス専用Campaign生成 接続報告

## 結果

サービス専用の週間投稿計画と毎日の投稿案で、参加者が承諾したCampaignを利用できるようにした。内部の`Group.id`をサービス識別子として維持し、サービスをまたぐCampaignはRepositoryと生成処理の両方で拒否する。

## 生成へ利用する情報

- 同じサービスに属する、受付中かつ期間内のCampaign
- 参加者本人と投稿パートナーが承諾したCampaign参加情報
- 公開済みで投稿パートナーへ割り当て済みの公式商品パック
- 商品の事実、対象者、FAQ、素材、必須表記、禁止表現
- 管理者が承認した商品用またはサービス共通の公式Knowledge
- 同じサービス・参加者へ適用できる外部成果計測URL

## 安全境界

- サービス画面のSlugからサーバー側でサービスIDを解決する。
- Campaign候補検索へサービスIDを必須境界として渡す。
- 毎日の投稿案生成時にも、選択済みCampaignの商品パックが同じサービスか再確認する。
- 他サービス、未承諾、停止中、期間外のCampaignを利用しない。
- 専用URLは既存の優先順位・有効期間・許可ドメイン検証を通し、使用時点のURLを履歴へ保存する。
- 個人Knowledge、他サービスKnowledge、未承認資料は利用しない。

## 実装対象外

- SNSへの自動投稿
- クリック・購入・成約の独自計測
- 報酬計算と支払い
- サービス間の商品・Campaign共有

## 確認項目

- サービス用週間計画がCampaign候補を利用できる。
- 同じサービスIDではCampaignを取得でき、異なるサービスIDでは取得できない。
- 毎日の投稿案生成でサービス境界を再検証する。
- 個人向け生成は従来どおり、サービスIDを指定しない経路を維持する。
