# サービス専用投稿パートナー詳細 実装報告

## 目的

サービス参加者が、自分の投稿パートナーの内容をサービス専用画面で確認・編集・停止できるようにする。

## 実装内容

- `/s/{serviceSlug}/bunshins/{bunshinId}` に詳細・基本設定画面を追加
- サービス専用の詳細取得・更新・停止APIを追加
- 一覧カードから詳細画面へ移動できる導線を追加
- 保存完了・失敗を画面内に日本語で表示
- 停止前に確認を表示し、完了後はサービス専用一覧へ戻す

## プライバシー修正

通常のサービスBunshin一覧と詳細は所有者本人だけを対象とする。サービスに参加しているという理由だけで、他参加者の投稿人格を閲覧できない。

サービス管理者にも通常投稿人格の閲覧権限を自動付与しない。将来、調査に必要な場合は目的、表示項目、監査ログを限定した専用機能として設計する。

## サーバー境界

- URLのサービスSlugから `workspaceId + groupId` をサーバー側で解決
- 詳細・更新・停止のすべてで `workspaceId + groupId + bunshinId + actorUserId` を照合
- クライアントからWorkspace・Groupを受け取らない
- POST/PATCHは同一Originを必須とする

## 次の段階

MS-2DでSNS設定と毎日の投稿案に、同じサービス境界を伝播させる。既存のWorkspace専用APIをそのまま流用せず、サービスSlugを起点にする。
