# OEM請求運用 実装報告

## 1. 調査した内容

- 確定MAU、OEM契約、内部請求台帳、請求状態遷移の既存実装
- Platform SUPER_ADMINと運営団体の権限境界
- 管理画面、CSV出力、外部請求書番号・入金参照番号の保存経路
- 3,001 MAU以上の個別見積月が自動請求されず残る仕様

## 2. 変更した範囲

- 全運営団体を横断する請求・入金管理画面
- 下書き、未入金、期限超過、入金済みの集計
- 経理用CSV出力
- 個別見積月への合意金額入力と請求台帳作成
- 期限超過・請求集計の共通Application関数
- 権限、テナント境界、CSV安全性、金額検証のテスト

## 3. 主要な設計判断

- 確定MAUは変更せず、個別見積金額は`TenantInvoice.amountYen`へ保存する。
- 個別見積の作成対象は同じWorkspaceに属する、確定済み、金額未確定、未請求の月に限定する。
- 正式な請求書と税計算は外部請求サービスの責務とし、本機能は内部台帳・債権管理に限定する。
- 決済Providerが未決定のため、Stripe等への直接依存は追加しない。

## 4. 実行した検証

- Application単体テスト
- Database単体テスト
- Web CSV単体テスト
- 全Workspace TypeScript型検査
- lint、全テスト、production build

## 5. 未解決事項

- 税務上の請求書発行、消費税・適格請求書番号の管理
- Stripe等のオンライン決済、Webhookによる自動入金反映
- 請求メールの自動送信と督促

## 6. 次Phaseへ進める条件

- 利用する決済・請求Provider、販売主体、返金・キャンセル方針を決定する。
- 発行者情報、税区分、適格請求書番号の運用方針を決定する。
- Provider接続用の本番資格情報はリポジトリ外で管理する。
