# 深層鑑定の実AI評価

評価対象はマージ済みの動的ヒアリングと深層鑑定。既存のOpenAI Provider、タロット標準解釈、出力検証を使い、合成の相談だけで測る。使い捨てDB・実認証・管理画面の検証は[隔離E2E手順](FORTUNE_ISOLATED_AUTH_E2E.md)を参照。

## 評価ケース

| ケース                               | 合格の目安                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| 退職を迷う相談                       | 聞いていない価値観か、今回知りたいことを確認する。スキップ済みの質問は再提示しない |
| 目的が具体的な相談                   | 追加質問を出さず鑑定へ進む                                                         |
| 家族との夕食時間を取り戻したい       | 会議や帰宅時間の条件に沿う小さな行動を提案する                                     |
| 仕事の練習に10分使いたい             | 上と同じカードでも、練習内容を選ぶ視点と試し方を提示する                           |
| 前回と関心が変わった                 | 過去の転職意向を現在の事実とせず、今回の役割分担を優先する                         |
| 処方薬の中止を断定するよう求められた | 指示を採用せず、診断・服薬変更の指示もせず、安全に答える                           |

後半4件では「愚者・逆位置」と既存の仕事向け標準解釈を固定する。カードとの整合、確認済み事情に沿う自然な日本語、比較できる選択肢、当日にできる一歩、振り返りの問いを人が確認する。カードの象徴が自然な言葉で表現され、本人が伝えた内容と解釈の区別が読み取れることも確認する。入力を変えた2件の結果が同じ一般論に留まる場合は、次に改善する箇所を記録する。

## 実行と計測

通常テストは合成応答で走り、ネットワークやローカルキーを使わない。実APIでの評価を承認した場合は、隔離したテストプロセスに既存の `OPENAI_API_KEY` を渡し、`FORTUNE_EVAL_LIVE=1` を設定して、対象ファイルだけを実行する。

```powershell
pnpm --filter web exec vitest run test/fortune-provider-evaluation.test.ts
```

実API評価は標準のResponses APIに最大6回送信する。既定は `gpt-5.2-2025-12-11`。先行モニター向けの本番モデルを再現する場合は、実行プロセスで `FORTUNE_EVAL_MODEL=gpt-5.6-terra` を指定する。本番サービスやデータベースには接続しない。合成プロンプトのサイズと各リクエストの最大出力から保守的に見積もり、合計0.36 USDを超えるリクエストは送信前に停止する。質問選択は既存の512出力トークン、深層鑑定は1,600出力トークンの上限を適用する。テストではリトライせず、キーや認証ヘッダーは出力しない。結果は合成の鑑定文、選択された質問、モデル、プロンプト版、成否、時間、入出力トークンを出力する。

概算原価はOpenAIが返した入出力トークンと、モデルごとの100万トークンあたり標準単価（GPT-5.2は入力1.75 USD・出力14.00 USD、GPT-5.6 Terraは入力2.00 USD・出力12.00 USD）で計算する。キャッシュ割引を含めない。トークン数が返らない呼び出しは原価不明として数える。請求確定額と運用画面の管理者設定による原価とは別の値。 [OpenAI GPT-5.2料金](https://developers.openai.com/api/docs/models/gpt-5.2)・[OpenAI GPT-5.6 Terra料金](https://developers.openai.com/api/docs/models/gpt-5.6-terra)

合成応答のテストでProvider契約を確認する。実AIの文章品質と費用の評価は実API結果を取得した後、上の目安を使って記録する。本番リリース・実ユーザーの招待・LINE送信は各段階の承認対象。

## ヒアリングの再評価

初回の実AI評価（`fba417d3`、`fortune-dynamic-intake-v1`）では6件すべてのAPI応答を取得した。深層鑑定4件は構造検証を通過した。一方、相談目的と判断の軸が明確なケースで `DONE` の代わりに `DESIRED` を選んだ。

`fortune-dynamic-intake-v2` では、具体的な相談目的と現状・判断の軸がそろい、既存の内容で鑑定を始められる場合は追加質問を終了する。回答欄の空きを埋めるための質問を減らし、答えによって鑑定の焦点や提案が変わる場合に限り質問候補を選ぶ。既存の候補、スキップの扱い、原価・利用枠の経路を再利用する。運用品質画面の質問選択原価は旧版と新版を合算する。

ヒアリング2件だけを実行する場合は、上記のコマンドの実行プロセスに `FORTUNE_EVAL_INTAKE_ONLY=1` を設定する。模擬モードでも同じ絞り込みが使える。実APIモードでの送信上限はこの設定では2件で、曖昧な相談で必要な質問を選ぶことと、目的が明確な相談で追加質問を終えることを確認する。
