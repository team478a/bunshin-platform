# 占い会員・通知基盤統一 実装報告

## 目的

占いを将来別サービスへ導入できるパッケージとして扱えるよう、参加状態と通知同意の二重管理を解消する。

## 実装

- 占いの利用可否を共通の有効なService会員状態と規約同意で判定する。
- 占い固有参加データは年齢確認と占い結果の参照に限定する。
- 週次LINE通知は共通通知設定の`FORTUNE_WEEKLY`を使用する。
- 利用者はスマートフォンの「占いの設定」から通知を開始・停止できる。
- 旧通知ON設定は有効会員に限って共通設定へ移行する。
- 共通側ですでに通知設定済みの場合、その設定を優先する。

## 段階移行

旧通知設定を共通通知設定へ移した後、アプリケーションから旧項目の参照と更新を停止した。運用確認後の移行で`fortune_participants.notification_enabled`と`withdrawn_at`を削除し、通知同意と退会状態の正本を共通Service基盤へ一本化した。

## パッケージ境界

占いCapabilityが所有するものは、年齢確認、カード、解釈、結果、通知Topicである。会員状態、規約同意、通知同意、退会は共通Service基盤が所有する。
