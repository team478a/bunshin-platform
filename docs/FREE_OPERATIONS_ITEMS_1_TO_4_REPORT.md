# 無料運用 優先4項目 完了レポート

## 1. 調査した内容

- ポイント自動付与、バッジ獲得、交換、失効、回収は、処理、管理画面、監査、照合、Production Gateまで実装済みだった。
- 30人・4週間の限定運用は、対象者上限、期間、停止、週次集計、結果CSVまで実装済みだった。
- 誤回収を元の回収単位で取り消す処理と専用画面が不足していた。
- 回収開始後の状態はポイント画面に表示されていたが、取消・完了の案内と週次LINEへの通知が不足していた。

## 2. 変更したファイル

- `packages/database/src/index.ts`: 誤回収を安全に取り消す共通処理を追加した。
- `packages/database/test/point-recovery-credit.test.ts`: 一部回収後の取消と再送時の冪等性を検証した。
- `apps/web/app/s/[serviceSlug]/manage/points/page.tsx`: 運営者向け取消画面と監査履歴を追加した。
- `apps/web/app/(app)/points/page.tsx`: 利用者向けに回収開始・取消・完了を表示した。
- `apps/web/src/services/weekly-progress-report-data.ts`: 利用者ごとの回収状態を週次レポートへ追加した。
- `apps/web/src/services/weekly-report-line-delivery.ts`、`weekly-report-line-scheduler.ts`: 状態を週次LINEへ接続した。
- `apps/web/src/http/service-reward-export.ts`: 取消監査を運営CSVへ追加した。
- 関連するWebテストと運用資料を更新した。

## 3. 主要な設計判断

- 取消は元の回収取引を必ず指定する。任意の追加付与で相殺せず、どの回収を戻したか追跡できるようにした。
- 既に回収したポイントは利用可能残高へ戻し、まだ回収していない額は `recoveryDue` から除く。取消後も `利用可能ポイント - 回収未済額 = 台帳合計` を保つ。
- 操作IDと元回収IDの両方で二重取消を防ぎ、取消理由と実行者を監査に残す。
- 利用者はポイント画面を開けば最新状態を確認できる。LINEは既存の週次配信へ載せ、無料運用で追加の即時配信回数を増やさない。
- 画像・動画の品質改善は、利用者の指定どおり無料運用の優先4項目には含めず、限定運用後に判断する。

## 4. 実行した検証

- 回収未済が残る一部回収状態を取り消し、回収済み分だけ利用可能残高へ戻ることを確認した。
- 同じ操作IDを再送しても二重返却されないことを確認した。
- サービス・Workspace・利用者境界、取消画面、監査、CSV、利用者通知、週次LINE接続を対象テストで確認した。
- database と web の型検査を実行した。

## 5. 未解決事項

- コード上の未実装はない。本番データを使う実操作は、デプロイとMigration後に行う必要がある。
- 回収操作直後のLINE個別プッシュは実装していない。利用者画面の即時表示と週次LINEで開始する。
- 画像・動画の追加品質改善は限定運用後の別ゴールとする。
