# 利用者向け画面 操作結果・表示崩れ監査

## 対象

- LINE・メール認証と認証後の戻り画面
- Service参加、利用同意、招待、ログアウト・退会
- 完成動画の確認、採用・不採用、投稿完了
- 投稿パートナーの基本情報、知識、記憶、話し方、通知、根拠確認
- スマートフォン幅で使う主要なフォームと操作ボタン

## 確認結果と対応

1. 送信後に表示が変わらず、完了したか判断しにくい操作が残っていた。
   - 共通の送信ボタンを追加し、処理中の文言表示と二重送信防止を統一した。
   - APIを直接呼ぶ画面にも保存・変更・削除ごとの処理中表示を追加した。
2. 完成動画ページでは、採用・不採用を決めた後も同じ選択肢が残っていた。
   - 決定後は選択肢を閉じ、現在の状態と次の操作だけを表示する。
3. LINE本人確認の失敗、保存失敗、通信失敗が通常の説明文に紛れていた。
   - 状態通知の見た目と文言を統一し、再実行できる場所を明確にした。
4. 完成動画ページは要素が素の縦並びで、iPhoneでは動画・ボタン・補足の区切りが弱かった。
   - 動画、接続案内、結果、補足をカードとして整理し、操作ボタンを画面幅に合わせた。
5. ログイン確認、通知再送、投稿パートナー設定の一部に、処理中表示がなかった。
   - 対象操作を無効化し、処理内容に応じた文言へ切り替える。

## 判断基準

- 押した直後に処理が始まったことが分かる。
- 処理中に同じ操作を重ねて実行できない。
- 成功後は完了状態または次の画面に切り替わる。
- 失敗時は未完了だと分かり、利用者が次に確認する内容が表示される。
- 主要操作はスマートフォンで横にはみ出さず、押しやすい幅を保つ。

## 範囲外

システム管理者・Service運営者だけが使う高密度の管理表は、利用者向け画面とは別の操作設計を持つため今回の統一対象外とした。機能を妨げる型・Lint・ビルドエラーは全体検証で確認する。
