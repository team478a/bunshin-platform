# 外部成果計測URL連携 Production Gate

更新日: 2026-08-26

## 1. 判定対象

外部成果計測URL連携を実利用者へ案内する前に、本番環境・最新main・テスト用Groupで実施する。一般利用者の募集可否とは別に、専用URLを使う商品投稿の開始可否を判定する。

記録するのは対象commit、実施日時、担当者、合否、許可ドメイン、GitHub／Vercelの証跡URLだけとする。完全URL、紹介Token、メール、投稿本文、顧客情報、報酬情報を証跡へ記録しない。

## 2. 自動確認

- CIのformat、typecheck、lint、test、build、databaseが成功している
- Prisma migration `20260826090000_add_external_tracking_production_gate`まで適用済みである
- `/api/health/ready`がreadyを返す
- URL選択Policy、危険URL拒否、CSV部分成功、コピー前再検証のテストが成功している

## 3. 管理者による本番確認

1. テスト用の外部サービスを登録する。
2. HTTPSのテスト用ホストを許可ドメインへ登録する。
3. Group共通、商品共通、参加者共通、商品＋参加者のテストURLを下書きで登録する。
4. URLと有効期間を別の担当者が確認してから使用を始める。
5. CSVへ正常行と、禁止ドメイン・期限逆転・重複の行を含めて取り込む。
6. 正常行だけが下書きとなり、異常行ごとに安全な理由が表示されることを確認する。
7. CSV原文、メール、完全URLがApplication／Vercelログへ出ていないことを確認する。

## 4. スマートフォンE2E

1. テスト参加者AでLINEログインする。
2. 対象Bunshinと商品から投稿案を作る。
3. 「あなた専用の紹介URLを入れました」、対象商品、期限、広告・PR表記が読めることを確認する。
4. 採用前にはコピーできず、採用後だけコピー操作が出ることを確認する。
5. コピー内容に正しいURLが1回だけ含まれることを確認する。
6. 「投稿しました」と感想を保存する。実SNSへの投稿は必須にしない。
7. 管理画面の使用履歴に日時、参加者、商品、使用URL Snapshotが残ることを確認する。
8. URLを停止し、同じ古い投稿案のコピーが拒否され、作り直しを案内することを確認する。
9. 新しいURLで作り直し、過去履歴のSnapshotが書き換わらないことを確認する。

画面幅375pxを基準とし、横スクロールなしで主要情報とボタンを操作できること、エラーが専門用語だけになっていないことも確認する。

## 5. Isolation確認

- 参加者Bには参加者AのURL、期限、使用履歴を表示しない
- 別Groupの管理者にはテストGroupのURLと履歴を表示しない
- 別商品・別CampaignのURLへfallbackしない
- 同じUserの複数Bunshinは同じGroup MembershipのURLを使用し、人格を成果帰属先にしない
- Group管理者に通常投稿本文、Memory、Knowledge、Feedback本文を表示しない
- LINE通知に完全URL、紹介Token、投稿本文を含めない

## 6. No-Go条件

次のいずれかがあれば開始しない。

- 誤った参加者、Group、商品、CampaignのURLが選ばれる
- 停止・期限切れ・開始前・禁止ドメインのURLがコピーできる
- URLなし不許可の商品でURLなし生成が続く
- CSVの異常行が保存される、または正常行まで失われる
- URL変更により過去の使用履歴が書き換わる
- LINE、ログ、監査に完全URLや秘密情報が意図せず出る
- クリック、成約、報酬、顧客情報を本システムが計測・保持する

## 7. Go記録

すべて合格後、管理画面の「本番開始の確認記録」で対象commitに`EXTERNAL_TRACKING_SMOKE`を記録する。確認の取消や新しいcommitの配備後は再確認する。`FINAL_APPROVAL`は本項目を含む全確認が揃うまで保存できない。
