# AI・検索サービス設定 Core 実装報告

## 1. 調査した内容

LINE設定で採用済みの環境分離、版管理、権限、暗号化境界、監査記録を確認し、OpenAI・Exa・Firecrawlにも同じ管理原則を適用した。

## 2. 変更した範囲

- OpenAI・Exa・Firecrawlの設定モデル
- DEVELOPMENT・STAGING・PRODUCTIONごとの版管理
- 日次・月次の米ドル予算上限
- APIキー未取得でも作成できる停止中の下書き
- APIキー暗号化Portと、平文を永続化層へ渡さないUse Case
- 設定変更の監査記録

## 3. 主要な設計判断

- 新規設定は必ず `DRAFT` かつ全体停止状態で作成する。
- APIキーは任意入力とし、準備前でもモデル・予算を決められる。
- APIキーを受け取った場合は暗号化済み値と末尾マスクだけを保存する。
- 1環境・1Providerにつき `ACTIVE` は最大1件とし、DBの部分一意Indexでも防止する。
- OpenAIだけモデル名を必須とし、検索Providerには不要なモデル設定を持たせない。
- 接続確認、ACTIVE化、実際のProvider呼び出しはAPIキー取得後の別作業とする。

## 4. 未実装

- 管理画面/APIと暗号化Adapter
- Provider別の実接続確認
- ACTIVE化・緊急停止操作
- 使用量集計による自動停止

これらは本Coreのレビュー後、秘密値を画面へ再表示しない条件で接続する。
