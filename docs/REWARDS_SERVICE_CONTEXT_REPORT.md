# ポイント・バッジのサービス別表示 実装報告

## 1. 調査した内容

- 利用者向けポイント・バッジ画面のWorkspace選択と試験利用判定
- サービス別ポイント交換設定、画像機能の利用許可、投稿パートナーへの導線
- 共通バッジとサービス独自バッジの表示範囲
- サービス内の活動、ヘルプ、週間レポート、投稿案からポイント画面へ進むリンク

## 2. 変更したファイル

- `packages/database/src/rewards-pilot-access.ts`: 本人が現在利用できるサービスをすべて取得
- `packages/application/src/badge-user-experience.ts`: バッジ画面へ対象サービスIDを伝達
- `packages/database/src/badge-user-experience.ts`: サービス独自バッジを選択中サービスへ限定
- ポイント・バッジ画面: 複数サービスの選択とサービス文脈の維持
- サービス内の活動・ヘルプ・週間レポート・投稿案: 遷移先URLへサービスを明記

## 3. 主要な設計判断

- Workspaceはポイント残高の単位、Serviceは利用許可・交換設定・独自バッジ・利用先の単位として分ける。
- 同じWorkspaceで複数サービスを利用できる場合、先頭の所属先を自動選択せず本人に選んでもらう。
- URLのWorkspaceとServiceが本人の有効な試験参加に一致する場合だけ画面を開く。
- サービス内のリンクにはWorkspaceとServiceの両方を付け、LINE内ブラウザでも選択を失わないようにする。
- 共通バッジは維持し、サービス独自バッジと共有先だけを選択中サービスへ限定する。

## 4. 実行した検証

- 同じWorkspaceに2サービスある場合に自動選択しないこと
- URLで指定したWorkspaceとServiceが一致する場合だけ選択すること
- 試験利用中のサービス一覧と最も早い終了日の取得
- 選択中サービス以外の独自バッジと共有先を返さないこと
- 型検査、Lint、テスト、Production build

## 5. 未解決事項

- 本番iPhoneで2サービスへ参加する確認用アカウントを用意し、切替表示を確認する。
- 共通ポイント残高がサービスを切り替えても同じで、使い道だけが各サービス設定へ変わることを確認する。

## 6. 次Phaseへ進める条件

- サービスAから開いた画面にサービスBの交換価格・停止状態・独自バッジが混ざらない。
- サービス選択後、ポイントとバッジの相互リンクおよび投稿案への導線が同じサービスを維持する。
