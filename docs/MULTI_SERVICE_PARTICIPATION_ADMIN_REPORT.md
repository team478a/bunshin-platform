# サービス参加承認画面 実装報告

## ゴール

運用担当者がサーバーやDBを操作せず、承認制サービスへの参加申請を確認・承認できるようにする。

## 画面

既存の`/groups/{groupId}/members`へ「承認を待っている参加申請」を追加した。管理画面を増やさず、招待、参加者状態、利用機能と同じ場所で管理できる。

表示する情報は申請者の表示名とメールアドレスに限定する。個人メモリー、投稿履歴、他サービスの情報は表示しない。

## 権限

- 対象サービスの有効な管理者
- 対象サービスと同じ団体のOWNERまたはADMIN
- 有効なSUPER_ADMINまたはOPERATOR

画面表示だけでなく、承認処理時にDBで権限、workspace、service、membership、`PENDING_APPROVAL`状態を再検証する。

## 操作

- 5文字以上の承認理由を必須にする
- 承認後は参加者を`ACTIVE`へ変更する
- 操作者、理由、変更前後の状態を監査ログへ記録する
- 承認済みの申請は承認待ち一覧から消え、通常の参加者設定へ移る
