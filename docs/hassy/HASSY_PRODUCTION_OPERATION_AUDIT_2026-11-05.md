## 本番管理画面の稼働監査

- 公開サービス画面は表示でき、参加手続き済みの利用者として開始導線まで進める。
- サービス管理画面の開始準備は、初回監査時の6 / 10項目から、問い合わせ先登録後に **7 / 10項目完了**へ更新された。

- 直近7日間のLINE送信、投稿案生成、採用・見送り、コピー・投稿完了、AI実行はすべて0件。
- したがって、設定上の準備は一部完了しているが、実利用者による一連の稼働はまだ確認できていない。

   - ハッシーをLINE起点で運用する設計に対し、メール参加が有効なため未完了になっている。
3. **利用規約とプライバシー**
   - ハッシー固有の公開済み利用規約・プライバシー文書がどちらも未登録。

### 自動配信開始時のAI生成停止

- 利用者がInstagram・08:00を選び「LINE配信を始める」を実行した。
- ハッシーのコンテンツテーマとInstagramプロフィールは本番APIで作成され、保存済みであることをVercelのリクエスト履歴で確認した。
- 続く発信方法（Social Account Strategy）の生成APIが2026-11-05 21:26:26 JSTにHTTP 409を返し、承認と自動配信の有効化までは進んでいない。
- 失敗はLINE接続ではなく、OpenAI呼び出し前のProvider実行許可（原価未確定、日次・月次予算、または実行予約）のいずれかでfail-closedになった可能性が高い。応答時間が短く、生成完了・生成失敗logが残っていないこととも整合する。
- 同じ利用者操作を繰り返す前に、本番管理画面のAI設定でOpenAIの利用状況、日次・月次予算、原価未確定、未完了の実行予約を確認する。
- 予算・原価安全策を緩和せず、原因を解消してから一度だけ再実行する。既に保存されたテーマとSNSプロフィールは再作成しない実装になっている。
- Provider実行許可の失敗は従来の実装では生成処理の診断logより前に発生するため、HTTP 409だけでは原因分類を確定できなかった。
- 後続診断用に、日次上限、月次上限、原価未確定、実行予約競合を安全な固定分類で記録する変更を作成した。内部例外文、APIキー、入力内容はlogへ残さず、予算・原価のfail-closed判定も変更しない。
- 対象テストは142件成功。変更2ファイルのLintも成功。Web全体の型検査はエラー出力なしで進行したが、7分超・約3.6GBまで使用したため環境負荷を避けて中断した。

### 2026-11-06 Provider原価未確定の確定診断

- 診断log反映後の07:44 JSTに利用者がハッシーの「LINE配信を始める」を再実行し、発信方法生成はHTTP 409で停止した。
- 固定分類は`PROVIDER_COST_UNKNOWN`であり、LINE接続、日次予算、月次予算、実行予約競合ではないことを確定した。
- 管理画面には、2026-11-01の`gpt-5-mini-2025-08-07`成功記録4件と、2026-11-02から11-05までの`gpt-5.2`失敗記録8件が原価未確定として表示された。
- 成功4件は入力・出力トークンが記録されており、OpenAI公式の標準価格表を証跡に原価を算出できる。
- 失敗8件は入力・出力トークンがなく、本番logで`provider cost is unknown`または`decision context is not ready`によりProvider呼出前に停止したことを確認した。正しい原価は0円だが、既存精算APIは正数しか受け付けず、正しい精算ができない。
- 0円精算を`FAILED`かつ入力・出力トークンなしの記録だけに限定し、証跡参照を引き続き必須とする修正を作成した。成功記録またはトークンのある記録への0円入力はDB repositoryで拒否する。
- 同時に、発信方法生成が409で停止した場合は「LINE配信は開始されていない」ことを利用者画面へ明示し、失敗直後の再描画で案内が消えないようにした。
- 対象テスト22件、Application・Database・Web型検査、対象lint、Prettier、`git diff --check`は成功した。ローカルNodeは22のためengine警告があり、正本のNode 24検証はPR CIで行う。

### AI予算・原価精算画面の簡略化

- 通常運用で判断する予算はProviderごとの月額上限を中心とし、日額停止上限と1処理の予約額は安全機構として「高度な安全設定」へ分離する。
- 原価未確定記録は1行ずつ処理させず、Provider・モデル・成否のまとまりを先に表示する。
- 同じまとまりには価格版を一括入力できる。失敗かつトークン記録なしのまとまりは、Provider未送信を運用ログで確認した場合に限り、0円を一括入力できる。
- 一括入力後も証跡参照と最終精算操作を必須とし、成功記録やトークンのある記録を0円にする既存のDB拒否は維持する。
- Providerごとの日額・月額停止、同時実行予約、原価不明時の停止判定は削除せず、利用者向けの判断項目と内部安全機構だけを表示上分離する。
