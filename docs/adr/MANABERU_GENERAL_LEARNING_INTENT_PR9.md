# 学習目的を既存の教材候補に保存する

個別学習の要望とヒアリング結果から得る構造化情報を、既存の教材候補 JSON の任意項目として保存する。教材候補の保存認可、要望版、原価記録、旧候補の読み取りを再利用する。追加の DB migration は不要。

分析には、学習の種別、目的、利用環境、サービス候補、操作ごとの成果と検証条件、必要な確認事項を含める。サービス名と成功条件は学習計画の候補として扱う。サービスの許可範囲、操作命令、実行と検証の結果は各責務の境界で決める。現行の検証用メモ教材は回帰テストと開発環境の既存経路として維持する。

本線確認時の main は `2bc17530`。#1625〜#1631 の実装を含む。#1632 の取り込みは作業ブランチに行われ、#1633 が main 向けで CI と Docker 検証済み。

## 初期接続

開発環境で操作教材が有効な AI スキル研修と、既存の Google Provider が選ばれている学習候補生成を対象とする。既存の構造化応答に分析を同梱し、同じ呼び出し・原価予約・候補保存を使う。分析の応答が不正または欠落した場合は、その生成を失敗として記録する。保存済み候補は再利用する。

## ブラウザ探索の比較対象

| OSS                                                       | 次工程で確認する点                                                                              |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| [Playwright](https://github.com/microsoft/playwright)     | 現行ワーカー、構造化実行、証拠取得、再実行の土台。                                              |
| [Stagehand](https://github.com/browserbase/stagehand)     | ローカル環境の DOM 取得と操作候補の扱い。既存 PR-2 の合成応答による試験は実モデルで再確認する。 |
| [Browser Use](https://github.com/browser-use/browser-use) | Python の探索器と既存 TypeScript の認可・ジョブ・証拠保存の連携コスト。                         |
| [Midscene.js](https://github.com/web-infra-dev/midscene)  | DOM で特定しにくい要素を視覚処理で補えるか、既存の操作検証や原価管理と共存できるか。            |
| [LaVague](https://github.com/lavague-ai/LaVague)          | 計画と実行の分離を参考にし、既存ワーカーへ適用できる範囲を比較する。                            |

公開資料上の比較。操作成功率や原価を比較するには、同じ検証環境・学習目的・成功条件での計測が必要。
