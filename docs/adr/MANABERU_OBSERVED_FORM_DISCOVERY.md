# 検証用フォームの入力とプレビューを探索する

既存のPlaywrightワーカー、候補選択API、操作レシピと画像付き教材を使う。フォーム検証は専用のレシピ版で実行し、既存カタログの上限と候補形式は維持する。検証用フォームの必要操作が8手順であることを基に、その版の探索・モデル選択を最大8回に制限する。

フォームでは名前付きの入力欄と未チェックの確認欄も画面から抽出する。モデルに送るのは操作候補のID・種類・表示名。入力値は検証画面に付属する固定の練習用データからワーカーが選ぶ。入力済みの欄、パスワード欄、読み取り専用欄は候補から除く。成功条件はプレビュー上に表示される完了メッセージとする。

対象は隔離された検証用ページ。外部への通信とフォーム送信は既存の隔離で禁止する。既存のProvider予算と利用台帳を使い、保存済みのレシピの再実行ではモデルを呼ばない。

## 検証方法

開発またはステージングで既存の候補選択APIを設定し、`discover-observed-form-model WORKSPACE_ID ACTOR_ID DEVICE REQUEST_ID` をブラウザワーカーに登録する。ワーカーの `once` または `serve` で処理し、`report-observed-model WORKSPACE_ID ACTOR_ID JOB_ID` で登録済みの利用量・原価を確認する。

同じWorkspace・実行者・端末で検証済みのレシピがある場合は再実行する。教材化には同じワーカーの `material WORKSPACE_ID ACTOR_ID RECIPE_ID REQUEST_ID` を使う。初回の検証対象は社内研修申請のプレビューで、受講者画面から対象を選ぶUIは後続とする。
