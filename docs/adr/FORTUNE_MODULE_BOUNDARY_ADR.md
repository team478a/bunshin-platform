# 占いモジュール境界 ADR

日付: 2026-09-16
状態: 採用

## 決定

占いは別製品や別システムとして複製せず、ワタシワークスのサービス基盤へ `FORTUNE` Capability として追加する。ただし、投稿支援、ポイント、他の分身の記憶とはデータと権限を分離する。

初期版は次の境界を守る。

- 占いサービスごとに運営者所有の占い分身を1体だけ関連付ける。
- 利用者はサービス参加者として登録し、占い分身の管理権限を持たない。
- 利用者が選べる入力は「恋愛」「仕事」「人間関係」のテーマだけとする。
- 78枚のカードと正位置・逆位置はサーバー側の暗号学的乱数で決め、AIに抽選させない。
- 1サービス・1利用者・日本時間の1日につき1件だけ記録できるよう、データベースの一意制約で再抽選を防ぐ。
- 結果を利用者が削除しても記録行は残し、同日の再抽選を許可しない。
- 新しい占いサービスは `enabled = false`、AI生成は `aiEnabled = false` で作る。
- 18歳以上の自己申告を参加条件とし、週1回のLINE通知は初期状態で無効にする。
- 課金、販売誘導、予約、ポイント付与、紹介報酬、公開結果URLは占い画面へ含めない。

## 理由

既存の認証、LINE、サービス参加、運営団体、AI利用記録を再利用できる一方で、占い内容が投稿支援や他サービスの個人データへ混入することを防げる。Capability とサービス設定の二重の停止手段により、知識・法務・運用準備が完了するまで公開しない構造になる。

## 実装順

1. `FORTUNE` Capability、カード抽選規則、保存モデル、停止スイッチ
2. 参加同意、今日の占い、結果、90日履歴、削除のスマートフォン画面とAPI
3. 468通りの承認済み基本解釈、AI生成と安全検査、基本文へのフォールバック
4. 希望者だけへの週次LINE通知、運営品質画面、クローズド試験

公開は、名称・ロゴ・運営者情報・利用規約・プライバシーポリシー・LINE設定・承認済みカード解釈が揃った後に別途判断する。
