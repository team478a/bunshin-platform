# SNS支援を権限付きの次の行動へ接続する

2026-11-02 / main #1433後

既存Barrier / Confirmation / SupportIntervention / Schedulerを拡張する。
別の推薦・質問・回答・見送り台帳、Cronは作らない。
SOCIALは行動の意味と無償支援、共通基盤は所属・同意・権限、
Webはサービス内の実装済み操作への導線を扱う。Hassyの人数特典やMUSEをSNS共通へ固定しない。

今回の機能単位:

- 採用後に投稿完了報告がない信号を既存判定器へ追加する。既存28日観測と自己申告の意味は維持する。
- 本人・所属・同意・Bunshin・SOCIAL Capability・SOCIAL.ACTIVITY_SUPPORT権限を表示と採用時に再検証する。
- 採用・回答の並行処理をBunshin単位で直列化し、回答の完全一致だけを再送成功にする。
- 再構築不能な回答要求だけを既存Confirmationのnullable JSONへ追加するmigrationを許可する。
  過去の要求を推測して埋めない。旧回答の再送は競合にし、保存済み支援の閲覧は維持する。
- 見送り理由は既存Intervention snapshotのfeedbackに保存し、caseの30日抑制も同じtransactionで更新する。
- 既存の進行中支援を新しい質問で隠さず、次の行動は1件に限定する。
- 案内は実装済みの無償操作だけとし、AIや外部操作を呼ばない。原価不明の有料機能・未提供機能を推奨しない。
  停止後の新しい回答・採用は拒否し、本人の完了・見送り記録は許可する。
- 人数による体験権限の自動発行は、特典catalog・期間・本部上限を保存する契約が未接続のため有効化しない。
  現行権限を読み取るだけで権限や無料原価上限を緩和しない。

API / 画面 / DB / 合成データテストを同じPRで接続する。本番設定や外部接続は変更しない。
