# CI の重複生成と待ち時間を減らす

`verify` と `database` のチェック名、実行機会、検証範囲を保つ。CI ジョブ内で同じ Prisma スキーマから生成したクライアントが存在する場合は共有する。`--ci-reuse` で準備した依存インストール内だけで生成物を再利用する。通常のローカルコマンドや本番ビルドでは生成処理を呼ぶ従来の動作を継続する。Turbo の成果物キャッシュとは別に、ジョブ開始時にそのランナーでクライアントを用意する。

型チェック、lint、単体テストは既存の順序で実行する。同じランナーでこれらをまとめて並行実行する試行では、当該区間が従来の6分55秒を超えたため採用しない。実装のアーキテクチャ検査、単体テスト、学習画面の E2E、Next.js の本番ビルド、PostgreSQL の統合・移行検証はいずれも実行する。Vite を使う学習画面の E2E と Next.js のビルドを同じランナーで並行実行し、どちらの失敗も `verify` に反映する。

追加のランナーを起動せず、PR の待ち時間とランナー実行時間を通常 CI の実測で比較する。
