# SNS利用実績に基づく案内候補と未回答質問の抑制

状態: 実装済み。検証結果は実装報告/PR参照。基準main 1bbb6cf0。対象は無料の情報案内だけ。

## 監査と判断

既存SocialActivityBarrierCase/Evidence/Confirmation/SupportInterventionが候補、根拠、本人回答、閲覧、採否、完了、見送りを保存している。Improvementは事業者向けの問題集計で、ユーザー向け提案台帳ではない。新たな同等台帳は作らず、既存の候補・本人確認・支援の状態遷移を利用する。

- 利用実績の案内を新しいevidenceCodeと専用supportKeyで識別する。MEDIA（画像利用枠）、EFFORT（複数媒体の準備）、EFFECT（紹介の成果確認）はルーティング用。利用増加を困りごとや悪い成果として確定しない。質問・選択肢は中立の専用文面にする。
- 従来の障壁候補を優先し、未回答/対応中の障壁の根拠を利用案内で上書きしない。利用案内は障壁集計、障壁の改善率、OEMの有料支援への昇格から除外する。完了した案内は再提案しない。
- 28日の保存済み画像生成成功request数（複数枚を二重計上しない）、実際の採用/コピー/投稿報告のあるSNSの種類数、既存の審査・確定済み紹介数を集計する。登録SNS数だけでは利用としない。原本イベントを新設しない。
- 閾値と未回答質問の間隔は独立したsocialUsageGuidancePolicy名前空間へ保存する。既存SNS設定v1の形式と冪等fingerprintは変更しない。共通ManagedFeaturePolicyの本部/OEM認可、revision、Groupロック、監査を再利用する。
- 未設定の初期値は画像成功5request、SNS2種類、有効紹介3件、未回答7日（設定2–90日）。OEMは本部設定後に閾値/間隔を減らせず、本部停止を解除できない。利用案内の個別対象は既存カテゴリ設定も適用する。
- GETでは書き込まない。画面で質問が実際に見えた後、本人認証・scope・Feature・現在条件を再確認したPOSTで、既存Case.nextEligibleAtを進める。抑制期間中の同じ表示の再送で期限を延ばさない。未回答の抑制中も表示済み質問へ回答できる。回答後の見送り抑制は既存の固定snapshotを維持する。
- 利用案内の内容は利用枠確認・複数媒体の手動準備・紹介状況確認。Credit/Entitlement付与、AI生成、SNS公開、接続、アカウント設定変更は実行しない。追加AI原価は0。実行機能が未提供/権限不明のまま有料自動化を勧めない。

ハッシー固有の段階・ブランド・紹介特典数値はWeb側に残し、SNS共通のルールへ混ぜない。新規table/migration/Cron/環境変数/Flagは不要。本番反映は別工程とする。

利用案内は観測末尾から48時間の鮮度制限、表示根拠の照合を追加する。新案内を既存のLINE自動通知へ流さない。
