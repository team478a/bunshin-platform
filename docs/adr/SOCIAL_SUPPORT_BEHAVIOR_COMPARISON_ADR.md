# SNS支援開始前後の固定観測

2026-11-02 / main dd9c88b2

既存Improvementの収集・管理者認可・少数セル抑止・週選択画面へ、SNS固有の読取Adapterを追加する。推薦・履歴テーブルやJobは追加しない。

- 選択週にacceptedAtがある支援を母集団とする。各支援の開始前7日 [開始-7日,開始) と開始後7日 [開始,開始+7日) を比較する。日数はUTC経過時間で固定し、週選択だけ既存JSTを使う。
- 両期間に投稿案採用・本人投稿完了報告が1回以上あった支援件数を同じ母集団で表示する。投稿回数や採用率、因果効果とは呼ばない。同じ本人の複数支援は別観測である。
- 開始後7日が読取時刻までに完了していない支援、開始時刻矛盾、記録時刻不明は集計を保留する。行数上限超過は不完全とし0件へ変換しない。
- MissionDecision / PostRecordを既存の正本として読む。投稿報告はcreatedAtとpostedAtの両方が該当期間内の場合だけ数える。後日の遡及報告で過去期間を確定したと扱わない。
- Workspace/Service/User/Bunshinの一致を検査し、管理者専用の既存経路へ接続する。本文・見送り理由・個人参照をWebへ出さない。既存5人抑止と件数範囲を使い、前後4項目の組合せにも少数セル抑止を適用する。
- 共通ApplicationにSNS指標を固定しない。SNS定義はcapability-social、Prisma読取はdatabase、表示ラベルはWebに置く。既存支援完了cohortの定義は変えない。
- 原価・SNS公開・負担軽減・障害日・未記録行動は未判定。本番設定・外部実行・migrationは追加しない。
