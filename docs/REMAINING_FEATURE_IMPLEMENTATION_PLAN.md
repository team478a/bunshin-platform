# 旧チャット照合後の残機能 実装計画

## 目的

旧Codexタスクと自動化プロジェクト内の関連会話を現行実装へ照合し、実装済みの案を除外したうえで、残作業を依存順に進める。

## R0 本番運用確認

- 自動Daily Mission生成から共通LINE受信までを実端末で確認する。
- 専用URLの使用開始・修正依頼通知を各1件確認する。
- 紹介URLのLINE共有とQR読取を実端末で確認する。
- Production GateへMigration、復元訓練、端末smoke、退会dry-run、LINE Go/No-Goの証跡を登録する。

完了条件は、対象commitと証跡をProduction Gateへ記録し、同じ日付の重複生成・重複配信がないことを確認すること。

## R1 保存商品機能の仕上げ

1. 利用者本人による保存商品の非表示と監査記録（実装済み・本番確認待ち）
2. 運営者の商品マスターと本人商品プロフィールの明示的な関連付け、および公開中の公式事実・必須表記・禁止表現の生成処理への接続（実装済み・本番確認待ち）
3. 商品別の作成、コピー、投稿完了、外部成果計測URL使用状況の集計（コード実装済み・本番Migrationと操作確認待ち）

削除は履歴を失わない論理削除とし、別利用者・別サービスの商品を操作できないことを必須条件とする。

## R2 別案生成

通常のDaily Missionは1日1件のまま維持する。別案は元Missionに紐づく追記型の派生案として保存し、通常Missionの一意制約を変更しない。

1. 派生案、生成試行、選択履歴のCoreとMigration（コード実装済み・本番Migration待ち）
2. 元Missionと同じWorkspace、User、Bunshin、Service、Campaign、許可済みURLの再検証（コード・API実装済み、本番確認待ち）
3. 原案と直近派生案の重複検査、日次上限、AI利用量・原価記録（コード・API実装済み、本番確認待ち）
4. 「別の案を見る」「この案を使う」「内容を直す」のAPI/UI（コード実装済み・本番確認待ち）
5. 30 WP交換との接続。生成失敗時は予約を解放し、生成成功後だけ確定する（コード実装済み・本番確認待ち）

初期上限は1 Missionにつき1派生案とし、無料枠や追加回数は利用実績を確認して別途決定する。

## R3 本人素材を集めるDaily Action

- 写真を1枚撮る
- お客様から聞かれた質問を記録する
- 30秒の音声メモを残す
- コメントへ返信する
- 過去投稿を改善する
- 今日は投稿しない理由を記録する

素材は本人所有のKnowledgeまたはEvidenceとして保存し、別の利用者や分身へ暗黙共有しない。素材不足時は投稿を捏造せず、追加質問を返す。

6種類の入力、本人専用保存、写真保存、通常投稿・別案生成への接続、追加質問はコード実装済み。本番MigrationとiPhone操作確認待ち。

## R4 週次レポート

投稿数だけでなく、確認、コピー、投稿完了、休み、素材追加、別案利用を集計する。本人向けLINEは要約と安全なDeep Linkだけを送り、投稿本文や個人Memoryを含めない。

参加者向けのやさしい週次レポート、運営者向けの全体集計・声かけ候補、ポイント・バッジ集計、過去12週の表示、個人情報を含めないLINE案内文の作成導線はコード実装済み。本番反映後のスマートフォン表示と実データ集計の確認待ち。

## R5 販売・拡張

- K1〜K8: 契約、座席、利用権、Credit、価格版、決済、返金、管理画面
- P5〜P7: Group独自ポイント特典、管理、30人・4週間検証
- AV-4D3〜AV-10: AI動画Provider、完成動画配布、Funnel、限定検証
- Phase 10: 100人検証後の承認型SNS投稿とmetrics取得
- Phase 11: BLOG Capability移行

販売・決済、SNS OAuth、自動投稿は、R0と継続率検証が終わるまで先行実装しない。

## 実装順

`R0運用確認`と`R1保存商品`を並行し、その後`R2別案生成`、`R3本人素材`、`R4週次レポート`へ進む。R5は30人・4週間または100人検証の条件を満たした機能から個別に開始する。
