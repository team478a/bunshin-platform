# 副業向け無料サービス: 紹介・画像クレジット Core

## 目的

副業向け無料サービスにおける、紹介URLからの流入、紹介成果、画像生成用クレジットの基盤を定義する。

この基盤は、外部アフィリエイトシステムの成果URL、既存のワークスペース共通ポイント、現金報酬とは分離する。

## 今回実装する範囲

- サービス参加者ごとの固定紹介コード
- 匿名の紹介クリック記録と有効期限
- 被紹介参加者1人につき確定紹介者を1人にする紹介関係
- 登録、初期設定完了、初回閲覧、初投稿、却下の成果状態
- サービス別の紹介特典ルールの版管理
- `サービス × 参加者` 単位の画像クレジット口座と追記型台帳
- 特典予定、付与、取消の冪等な記録単位
- 自己紹介を拒否するアプリケーション境界

## 分離方針

### 外部成果計測URLとの分離

既存の `ExternalTrackingLink` と `{{referral_url}}` は、商品・キャンペーンへの外部URLを投稿へ差し込む用途である。

今回追加する紹介コードは、ワタシワークスの個別サービスへの新規登録流入専用とする。投稿テンプレートへ入れる場合も、後続Phaseで `{{service_referral_url}}` を新設し、既存の外部URL置換を流用しない。

### ポイントとの分離

既存 `PointAccount` は `workspaceId + userId` 単位である。同じユーザーが同一ワークスペース内の複数サービスに参加した場合、紹介特典の画像クレジットを共有してはいけない。

そのため `ServiceCreditAccount` と `ServiceCreditLedger` を `workspaceId + groupId + groupMembershipId + userId` で拘束する。ユーザー画面の表示名は後続管理画面から設定可能にするが、Coreでは画像クレジットとして扱う。

## 安全性

- クリック記録へ生のIPアドレス、User-Agent、メールアドレス、LINE IDを保存しない。
- 紹介コード、クリック、紹介、特典、口座、台帳のすべてを `workspaceId + groupId` で関連付ける。
- 紹介関係は被紹介Membershipごとに1件だけ確定できる。
- 紹介特典は `referralId + ruleId + beneficiaryMembershipId` を一意にし、同じ成果の二重付与を防ぐ。
- 台帳は更新・削除ではなく追加記録を基本とし、訂正は `REFUND` または `ADJUST` の逆方向エントリで行う。
- 現金、換金、譲渡、多段紹介、動画生成特典は今回実装しない。

## 後続Phase

1. 紹介コード発行、`/r/{code}`、クリックから登録への引き継ぎ
2. 成果判定ジョブ、特典ルール評価、クレジット付与・失効
3. 利用者の紹介画面、LINE共有、QRコード、残高・履歴
4. 管理者のルール、手動調整、保留・却下、不正確認、CSV
5. 公式キャンペーン投稿、`{{service_referral_url}}`、PR表記、媒体別集計
6. 画像生成時のサービスクレジット消費と失敗時返却

## 今回実装しないこと

- 公開紹介ページ、QRコード、LINE共有UI
- Cookie・一時トークン・last eligible referral の実行処理
- 画像生成処理との残高接続
- 公式キャンペーンの配信・生成・計測
- 不正スコアリング、電話番号・端末識別、IP保存
- 現金報酬、換金、ポイント譲渡、多段紹介、課金
