# グループ限定SNS画像生成 Pilot 0検証計画

## 1. 目的

Phase 7-Iの画像生成実装へ進む前に、10件の実際の投稿テーマを使い、生成方式、原価、安全性、評価手順を小規模に確認する。Pilot 0では一般ユーザーへ機能を公開せず、画像生成APIをDaily Mission画面へ接続しない。

本書とCSVテンプレートは検証準備の正本である。実際のAPI実行は、対象Group、予算、評価者、テーマ、人物素材方針の承認後に行う。

## 2. 検証する4方式

| ID  | 方式                                              | AI画像生成 | 日本語文字   |
| --- | ------------------------------------------------- | ---------- | ------------ |
| A   | GPT Image 2 lowによる完成画像一体生成             | 全体       | AI描画       |
| B   | GPT Image 2 mediumによる完成画像一体生成          | 全体       | AI描画       |
| C   | GPT Image 2 lowによる人物・背景＋テンプレート合成 | 素材だけ   | システム描画 |
| D   | 登録素材＋テンプレート合成                        | なし       | システム描画 |

方式A・Bは比較対象であり、標準実装候補ではない。標準候補は方式C、AI素材が不要または登録済みの場合は方式Dとする。

モデル候補は`gpt-image-2`とする。実行時は利用可能なquality、snapshot、Rate Limit、料金をOpenAI公式情報と管理画面の接続確認で再確認し、検証記録へ固定する。モデルaliasや料金をDomainへ固定しない。

## 3. 検証単位と件数

- 10テーマ × 4方式 = 最大40出力
- 各テーマの投稿目的、対象者、見出し、画像指示を固定する。
- 同じテーマ内で方式以外の入力条件を変えない。
- Provider障害によるシステム再試行は比較出力数へ含めず、原価には含める。
- 評価者が結果を見てからPromptを変更しない。修正試験は別attemptとして記録する。

最初の2テーマで安全なスモーク確認を行い、問題がなければ残り8テーマへ進む。一度に40件を投入しない。

## 4. テーマの条件

10テーマは実際の対象GroupとCampaignで利用する内容から選ぶ。

- `ORGANIC`、`PRODUCT_RELATED`、`ADVERTISEMENT`を含める。
- 人物あり・人物なしを含める。
- 短い見出し、箇条書き、CTAを含める。
- 商品投稿では公開中Product Pack Versionと広告表記を使用する。
- 個人情報、顧客情報、秘密情報、未公開商品情報を含めない。
- テーマCSVへ投稿本文全文、Memory、Knowledge、API Key、人物画像URLを書かない。
- 人物素材を使うテーマは、Provider送信を含む個別同意が確認できたものだけにする。

入力は`docs/templates/group-image-pilot-themes.csv`を複製して作る。実データ入りCSVはリポジトリへコミットしない。

## 5. 実行前の承認

Platform Adminが次を確認し、追記型の検証記録へ残す。

- 対象Production commit
- 対象Group、Campaign、Product Pack Version
- 評価者と実行者
- 10テーマの安全確認
- 人物素材の有無と同意
- OpenAI画像生成の接続状態
- 1日上限、検証全体上限、停止金額
- Storage保存先、閲覧者、削除予定日
- 全体緊急停止が利用可能であること

承認前はAPIを呼ばない。API Key、人物画像、署名URLを承認記録へ保存しない。

## 6. 実行順序

1. 全体停止中であることを確認する。
2. 対象Groupだけを検証対象として記録する。
3. テーマ1、2を方式D、C、A、Bの順で実行する。
4. 日本語文字、サイズ、MIME、原価、秘密情報、Storage権限を確認する。
5. 停止条件に該当しなければ、残り8テーマを実行する。
6. 各テーマの4画像はランダムな表示順へ変換し、評価者へ方式名を見せない。
7. 評価結果をCSVへ記録する。
8. 集計後、画像と一時素材を保持方針に従って削除する。

方式A・B・Cの実行はRate Limit内で直列または低い並列数に制限する。ボタン連打やHTTP再送で新しい課金リクエストを作らない。

## 7. 評価方法

評価者は`docs/templates/group-image-pilot-evaluations.csv`へ次を記録する。

- 生成成功
- 日本語文字の正確性
- 人物の自然さ（1〜5）
- 投稿内容との一致（1〜5）
- Instagramでの視認性（1〜5）
- そのまま採用できるか
- 再生成が必要か
- 生成時間
- 実原価
- 不採用理由

方式名は評価完了後に結合する。自由記述へ個人情報、Prompt全文、画像URLを書かない。

## 8. 集計式

- 生成成功率 = 成功出力数 ÷ 実行出力数
- 初回採用率 = 初回で採用可能な出力数 ÷ 成功出力数
- 再生成率 = 再生成が必要な出力数 ÷ 成功出力数
- 日本語文字正確率 = 文字が正確な出力数 ÷ 文字を含む成功出力数
- 平均生成時間 = 成功・失敗を含むProvider呼び出し時間の平均
- 1回原価 = Providerへ課金された実原価 ÷ Provider呼び出し数
- 1採用画像原価 = 採用画像へ至る全attempt実原価 ÷ 採用画像数

方式Dのテンプレート描画処理にはProvider原価0を記録するが、処理時間とStorage費用を別項目として記録できるようにする。0除算時は率を0とせず`N/A`とする。

## 9. 即時停止条件

次のいずれかで残りの実行を停止する。

- 他Workspace、他Group、他User、他Bunshinの情報が出力または参照された。
- API Key、署名URL、個人情報、Promptの秘密部分が通常ログへ出た。
- 同じidempotency keyで二重課金が発生した。
- 予算上限またはProvider Rate Limitへ到達した。
- 本人同意のない人物素材がProviderへ送信された。
- 重大な広告安全違反、危険な画像、不正MIMEが発生した。
- Storageが公開状態、または権限のない利用者から取得できた。
- 2テーマのスモークで日本語文字合成、1080×1350px出力、削除処理のいずれかが失敗した。

停止後は自動再開しない。原因、影響範囲、課金額を秘密情報なしで記録し、人間承認後だけ再開する。

## 10. Pilot 0完了条件

- 10テーマと4方式の評価欄が埋まっている。
- 失敗・再試行を含む実原価を照合できる。
- 日本語文字、人物、内容一致、視認性を同じ尺度で評価できる。
- 画像・サムネイル・一時素材の削除を確認できる。
- API Key、人物素材、画像Base64が通常ログへ残っていない。
- 重大なIsolation・広告安全・二重課金問題が0件である。
- 標準方式と採用理由をMarkdownで記録している。

## 11. I2へ進む条件

Pilot 0は製品のGo判定ではなく、実装方式の選定である。次を人間レビューしてからI2のDomain / DB PRへ進む。

- 標準方式をCまたはDのどちらにするか
- 人物素材を初期実装へ含めるか
- 採用画像と不採用画像の保持期間
- 初期の日次・月次・参加者別上限
- 実測に基づく検証予算
- Group管理者の集計閲覧範囲
- Pilot 1の50テーマへ進む時期

一般ユーザー公開、複数ページ、他サイズ、自動投稿、動画生成は、この承認に含まれない。
