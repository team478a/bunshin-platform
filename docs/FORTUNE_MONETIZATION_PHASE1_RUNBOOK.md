# 月と星のオラクルの単発販売検証

対象 Service は `watashi-fortune`。検証環境で占い、AI、個別化、動的ヒアリング、深層鑑定を有効にする。規約、プライバシーポリシー、特定商取引法の表示を用意する。提供時期、返金の条件と申請先は、商品設定と公開文書で揃える。開始価格案は税込1,980円。運営者が商品設定に入力し、最終確認画面の内容を確認する。

1. 既存の決済設定に Stripe テストアカウントを接続する。署名付き Webhook に `checkout.session.completed`、`checkout.session.expired`、`payment_intent.payment_failed`、`charge.refunded` を設定する。
2. 年齢確認済みの参加者で、商品詳細と Stripe 最終確認画面の価格、回数、提供時期と返金条件を確認する。決済画面から戻って再開しても購入が増えないことを確認する。
3. テストカードの拒否と成功を確認する。購入画面の戻りリンクを先に開いても、入金イベントがなければ鑑定権限が付かないことを確認する。同じイベントを再送しても購入・鑑定が増えないことを確認する。
4. 個別化に同意し、ステラのヒアリングで相談内容を確認して深層鑑定を開始する。提供済みの購入、同じ鑑定の追加質問回数、鑑定履歴、AI使用量を確認する。
5. 生成失敗時は購入履歴で未提供であることを確認する。本人に相談内容を再確認して再試行してもらう。対応できない場合は公開済みの条件に沿って Stripe 側で権限のある担当者が返金する。Webhook 到達後に未提供分と追加質問が停止し、部分返金の累計額が購入履歴と一致することを確認する。
6. 決済の存在が不明な場合は管理画面の購入IDを Stripe の Checkout の client reference または PaymentIntent の metadata (purchase_id) と照合する。最初の Checkout が未確定の間は同じ購入から再開する。期限切れ・返金のイベントは Stripe から再送できる。購入状態を手動で入金済みに変更しない。

Stripe テストの証跡には対象環境、コードSHA、Checkout・イベント・購入ID、結果とAI原価の記録有無を残す。カード番号、相談本文、鑑定本文は転記しない。

本番へ進む前に、管理者が承認済みの表示・問い合わせ先と返金手順を確認し、コード・DB・本番の接続を検証する。初回の実請求と販売有効化は明示承認後に行う。
