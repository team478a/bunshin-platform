# サービス別ポイント交換設定 実装報告

## 1. 調査した内容

- 共通ポイント交換カタログと、予約・確定・解放・返却処理
- 別の投稿案と投稿画像の交換処理
- サービス運営者向けポイント・バッジ管理画面
- 利用者向けポイントの使い道表示とサービス別集計

## 2. 変更したファイル

- Prisma Schema / Migration: サービス別の交換価格と有効状態
- `packages/application/src/point-redemption.ts`: サービス設定の適用と交換時価格確認
- `packages/database/src/index.ts`: サービス・本人の範囲確認、価格適用、利用履歴へのサービス記録
- サービス管理画面: 2特典の有効・停止、必要WP、変更理由、監査履歴
- 投稿案・画像・利用者ポイント画面: サービス別カタログの参照
- サービス集計・CSV: 当該サービスで消費したポイントだけを集計

## 3. 主要な設計判断

- 実装済みの交換機能だけを設定対象とし、実行処理のない任意特典は作成させない。
- 未設定のサービスは共通カタログの初期価格を継承し、既存運用を変えない。
- サービス設定がある場合は共通価格を上書きし、停止中の特典は一覧と交換処理の両方で無効にする。
- 画面表示後に価格が変わる可能性を考慮し、残高減算と同じ処理内で最新価格を再確認する。
- 消費TransactionへサービスIDを保存し、別サービスの利用を運営集計へ混ぜない。
- 設定変更者、変更理由、変更前後を既存のサービス監査ログへ保存する。

## 4. 実行した検証

- サービス価格の上書きと停止設定の適用
- サービス・Workspaceを越えた参照の拒否
- 表示価格変更時の交換拒否
- 投稿案と画像交換へのサービスID・最新価格の伝播
- Prisma validate / generate、型検査、Lint、テスト、Production build

## 5. 未解決事項

- 交換対象そのものを追加する場合は、先に対応する実行機能を実装する必要がある。

## 6. 次Phaseへ進める条件

- 本番で一方の特典を停止し、参加者画面から消えることを確認する。
- 必要WPを変更し、表示・確認・減算・サービス集計が同じ値になることを確認する。
