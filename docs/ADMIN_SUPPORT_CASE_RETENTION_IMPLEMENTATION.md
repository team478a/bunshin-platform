# 管理者問い合わせ記録の90日保持

## 状態

実装・自動テスト済み。PRレビュー、CI、マージ、本番デプロイ、Productionでの初回実行は未完了。

## 方針

- `SupportCase` は `RESOLVED` かつ `resolvedAt` が90日以上前の場合に削除対象とする。
- `SupportCaseNote` はケース削除時に既存の `onDelete: Cascade` で同時削除する。
- 未解決ケースは作成から90日を超えても削除しない。解決後に再オープンされれば削除対象から外れ、再解決時の `resolvedAt` を起点に90日を数え直す。
- `resolvedAt` がNULLの古い解決済み行は、誤削除を避けて自動削除しない。手動確認対象とする。
- 日次Cronは1回につき最大10バッチ（各100件）を処理する。残件がある場合は次回実行へ持ち越す。
- 削除クエリは候補IDだけでなく現在も `RESOLVED` かつ期限超過であることを再確認し、同時に再オープンされたケースを削除しない。
- DB schema変更を伴わないためmigrationは不要。バックアップの物理保持期限はSupabase側の設定に従い、本処理による行削除と同時に即時消去されるとは限らない。

## 変更範囲

DB packageの期限判定・上限付き削除、内部Cron endpoint、日次スケジュール、回帰テスト、運用方針文書。
本番DBへの実行、デプロイ、問い合わせデータの手動削除は行っていない。

## 次のGate

レビューとCI成功後にmainへマージし、通常のProductionデプロイを行う。デプロイ後、Cronの認証・実行ログと件数を確認する。古い`resolvedAt = NULL`行は自動削除されないため、件数を確認して別途判断する。
