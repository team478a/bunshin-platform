# 営業・OEM提案向け Capability Catalog

技術状態の正本は[機能台帳](20261106_FUNCTION_INVENTORY.md)、販売Go/No-Goは[実運用導線](20261106_SERVICE_OPERATION_READINESS.md)。ここでは顧客向けの言葉へ置き換える。実績・効果・完全自動化は未確認のため表現しない。

## 提供区分

- **現在説明可能**: コードと画面があり、デモ/先行テストの範囲を明示できる。
- **先行テスト必須**: 実利用成功、外部接続、決済、完走の証拠が不足。
- **将来構想**: 未実装または本番提供を確認できず、契約機能として約束しない。

## ハッシー（SNS支援）

- 対象: 日々のSNS発信を続けたい企業・店舗・個人事業者。
- 悩み: 毎日何を投稿するか決められない、発信が止まる、成果を振り返れない。
- できること: 企業情報と発信目的を登録し、SNSプロフィール、発信テーマ、週間計画、毎日の投稿案、採否/コピー/投稿完了、活動記録を一つの流れで扱う。専用LINEから戻れる。
- メリット: 「今日やること」を一つに絞り、文章作成と振り返りを同じ履歴へ残せる。
- 特徴: 1ユーザーが目的別のBunshinを持ち、別BunshinのMemoryを混ぜずに運用する。
- 現在提供可能: 公開入口、メールlogin、初期設定、専用LINE接続は本番成功確認。投稿支援のコードは広く存在。
- 先行テスト: AI戦略生成、日次LINE受信、投稿完了、90日Roadmap、分析、Instagram公式接続/投稿。
- 将来構想: Muse、完全自動投稿、高度動画。現在提供中とは説明しない。
- 営業条件: AI原価未確定のP0を解消し、1名の通し成功まで一般販売しない。

## マナベルスタイル（AI研修）

- 対象: AIを業務で使えるようになりたい個人・企業研修受講者。
- 悩み: 固定教材を見ても実務へ移せない、何を練習すべきか分からない、中断すると戻れない。
- できること: 初期profile、課題、回答、AI評価、次の課題、再開、進捗確認。動的方式では自由希望から教材候補と実践計画を作るコードがある。
- メリット: 学習閲覧だけでなく、本人の実践と結果確認を履歴にできる。
- 特徴: 固定教材方式と自由希望起点の動的方式を分離し、どちらも共通のEnrollment/回答/原価/権限基盤を使う。
- 現在提供可能: 固定教材の内部先行テスト候補。管理・期間・保持・LINE・原価機能は実装済み。
- 先行テスト: 登録から評価/完走、実AI品質、再login、LINE、期間終了。動的方式はWave 0全体。
- 将来構想: Provider比較と新ツール練習テーマ。効果実証済みとは表現しない。
- 営業条件: 固定教材と動的方式の提供範囲を契約書・画面・提案書で分ける。

## マナベルスタイル副業版

- 対象: 自分の条件に合う副業を選び、90日で試したい人。
- 悩み: 候補が多く選べない、計画だけ作って実践が続かない。
- できること: 希望/時間/経験のヒアリング、複数候補、本人選択、90日Roadmap、実践、check-in、計画revision。
- メリット: 候補提案で終わらず、既存AI研修の課題と進捗へ接続できる。
- 特徴: 物販専用に固定せず、安全性ruleを通した候補型。
- 現在提供可能: コードデモと内部先行テスト。
- 先行テスト: 専用Service/Program、非物販候補、実AI品質、90日運用。
- 将来構想: 追加副業カテゴリ。候補数を増やす開発は利用確認後。

## 占いサービス

- 対象: 自社ブランドで日次/週次のカード占いを提供したい事業者。
- 悩み: 標準解釈と個別メッセージ、履歴、通知を安全に運用しにくい。
- できること: カード抽選、承認済み標準知識、AI個別化、履歴、評価、LINE通知、利用資格/上限。
- メリット: 知識版と個別生成を分け、OEMごとに設定できる。
- 特徴: 個人化Bunshin/Memoryを明示範囲で使い、他利用者と混ぜない。
- 現在提供可能: コードデモ。
- 先行テスト: 公開Service、知識版、実reading、保持、LINE、原価。
- 将来構想: Package upgrade。公開実績が確認できるまで販売しない。

## AI物販プログラム

- 対象: 物販を小さく試し、継続判断をしたい参加者。
- 悩み: 最初の一週間の行動が曖昧、商品状態と次の作業がつながらない。
- できること: 参加、商品/反応/販売状態、毎日のAction、無料7日、Day7判定、有料90日Offer、決済・期限管理。
- メリット: 無料期間の行動実績をもとに継続を判断できる設計。
- 特徴: AI研修と同じProgram/Action/Commerce基盤を再利用。
- 現在提供可能: コードデモ。
- 先行テスト: FREE_7D、LINE、test決済、PAID_90D、返金/失効。
- 将来構想: 商品探索の高度化。実運用前に追加しない。

## メディア・アンバサダー支援

- 対象: 商品の公式素材を配布し、参加者の発信と成果を把握したいメディア/OEM事業者。
- 悩み: 素材、Campaign、投稿支援、紹介成果、特典が別々に管理される。
- できること: 参加者、商品/公式素材、Campaign、投稿案、活動実績、紹介URL、外部成果、point、badge、特典。
- メリット: 投稿準備から成果確認まで同一Serviceで扱える。
- 特徴: 千ノ国向けの既存構造を捨てず、共通Campaign/Product/Trackingへ接続する。
- 現在提供可能: 千ノ国を使った限定pilot候補。
- 先行テスト: 一Campaign、素材利用、成果取込、最低限の特典。
- 将来構想: 高度gamification。point/badgeの追加開発は利用実績後。

## OEM・ホワイトラベル

- 対象: 自社ブランドでSNS支援・研修・メディア等を提供したい事業者。
- 悩み: ブランド、参加者、LINE、利用量、契約、請求をサービスごとに作り直したくない。
- できること: テナント/ブランド、Service/Feature、member、専用LINE/email、商品/契約、利用量、Stripe、請求書のコード基盤。
- メリット: 同じ共通基盤でServiceごとの権利とデータを分離できる。
- 特徴: ProviderをCoreから分離し、OEMごとの設定と費用を追跡する。
- 現在提供可能: 要件説明と限定pilot設計。全面提供の通し証拠はない。
- 先行テスト: 一社の登録から請求preview、二tenant分離、domain、LINE、決済。
- 将来構想: 顧客アカウント移管/事業譲渡。現時点は未実装。
