# 営業・OEM提案向け Capability Catalog

技術状態の正本は[機能台帳](20261106_FUNCTION_INVENTORY.md)、販売条件は[実運用導線](20261106_SERVICE_OPERATION_READINESS.md)。コード公開済み、実利用成功、販売GOを同じ意味で使わない。

## 提供区分

| 区分                 | 意味                                                |
| -------------------- | --------------------------------------------------- |
| 営業説明・画面デモ可 | 公開コード/画面を説明できる。実績や効果を約束しない |
| 先行モニター可       | 明示した範囲・人数・停止条件で実運用検証できる      |
| 一般販売GO           | 通常顧客が開始から価値到達まで完了できる証拠がある  |
| 将来構想             | 現在の契約へ含めない                                |

一般販売GOは0。一方、全サービスの営業説明を禁止する結論ではない。

## ハッシー

対象は日々のSNS発信を続けたい企業・店舗・個人事業者。企業情報、発信目的、SNSプロフィール、テーマ、週間計画、投稿案、採否/copy/投稿完了、活動記録を一つの流れで扱う。

現在説明できるのは、1 User:N Bunshin、Bunshin単位のMemory分離、LINE起点の「今日やること」、投稿支援の既存画面。認証・初期設定・専用LINE接続は本番成功を確認した。

#1481/#1482の修正コードは公開済みだが、実データ精算と戦略再実行が未完了。P0復旧前に「毎日自動配信中」「Instagramへ自動投稿可能」と販売しない。完全自動投稿、Muse、高度動画は将来構想。

## マナベルスタイル

対象はAIを業務で使えるようになりたい個人・企業研修受講者。

固定教材方式は、定義済み課題、回答、AI評価、次課題、再開、進捗の流れとして説明・デモできる。動的方式は自由希望から候補/計画/相談/次課題を作る別方式であり、固定教材の提供実績を流用しない。

固定教材は1名の先行モニター候補。動的方式はDefinition/Pilot/費用/実端末Gate後。どちらも「研修完走実績」「効果実証済み」と表現しない。

## マナベルスタイル副業版

希望、時間、経験、制約から物販以外を含む候補を提示し、本人選択、90日Roadmap、実践、check-in、revisionへ接続するコードがある。

既存Training Programを再利用する点を特徴として説明できる。専用Service/Programと本番利用は未確認のため、一般販売せず、内部デモと限定先行テストに留める。候補カテゴリ追加は保留。

## 占い

card抽選、承認済み標準知識、AI個別化、履歴、評価、LINE、OEM設定の公開コードを説明できる。

公開slug、package有効化、承認Knowledge版、実reading、LINE受信を確認してから先行モニターへ進む。「本番公開中」「個別化効果確認済み」と表現しない。

## AI物販

FREE_7D、商品/反応/販売状態、Daily Action、Day7 Offer、PAID_90D、決済/期限管理の構造を説明できる。

最初の先行範囲は実決済を含めず、FREE_7DからOfferまで。Stripe test modeの購入/Webhook/返金/失効確認後に有料pilotを判断する。商品探索高度化は保留。

## メディア・アンバサダー

商品/公式素材、Campaign、投稿支援、活動、紹介URL、外部成果、point、badge、特典の公開画面を説明できる。

千ノ国の既存Serviceを代表pilotとし、一Campaignだけで素材→投稿支援→成果取込を確認する。全gamification機能を最初から販売範囲に入れない。

## OEM・ホワイトラベル

tenant/brand、Service/Feature、member、専用LINE/email、利用量、契約、Stripe、請求書の基盤を説明できる。

最初のpilotは既存一括作成入口、二tenant分離、利用者登録、人数集計、請求previewまで。独自domain、実決済、返金、顧客アカウント移管は別条件。顧客移管/事業譲渡は未実装。

## 使用しない表現

「全機能本番稼働済み」「完全自動投稿」「導入実績多数」「効果実証済み」「全SNS公式連携済み」「AIが無承認で自動改善・公開」。CI、mock、fixture、公開routeの存在を利用効果へ置き換えない。
