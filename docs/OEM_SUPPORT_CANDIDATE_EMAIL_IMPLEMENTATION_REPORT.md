# OEM支援候補メール通知 実装報告

## 1. 調査した内容

既存のサービス別Resend設定、配信テンプレート、登録完了メールWorker、OEM支援候補と方針Snapshotを確認した。登録完了配送は一意制約が登録用のため、配送履歴の兼用は行わない。

## 2. 変更した内容

- OEM支援候補専用の冪等なメール配送履歴。
- 有効な`SERVICE_OWNER / SERVICE_ADMIN`だけを送信先にするキュー生成。
- 既存のServiceメールProviderと暗号化済み資格情報の再利用。
- 5分間隔のWorker、3回上限の再試行、Provider冪等キー。
- `OEM_SUPPORT_CANDIDATE`テンプレートと、未設定時の安全な既定文面。

## 3. 主要な設計判断

- 利用者本人には送信せず、Service運営管理者だけに送る。
- `DISABLED`、メール停止、未検証Providerでは送信しない。
- メールは管理画面への案内だけとし、自動営業、契約変更、課金を行わない。
- 配送時の宛先、文面、方針をSnapshotとして保存する。

## 4. 未解決事項

- 本番Providerを使った実送信は未実施。
- LINEによる運営者通知はこのPRに含めない。

## 5. 次Phaseへ進める条件

MigrationとCI成功後、テスト用Serviceの運営者宛てに1件送信し、重複送信されないことを確認する。
