# 占いパッケージ導入機能 実装報告

## 目的

占い機能をワタシワークス内の別Serviceへ導入し、将来は運営団体向けパッケージとして提供できる状態にする。

## 導入手順

1. システム管理者が運営団体の契約設定で「占いパッケージの新規導入」を許可する。
2. システム管理者がサービス作成画面で「占いサービス向け」を選ぶ。
3. 運営団体と既存または新規プロジェクトを指定し、非公開でServiceを作る。
4. Service運営者が「占いの公開準備」で「占いパッケージを準備する」を1回押す。
5. 専用の占い担当と標準解釈468件が、非公開の状態でまとめて導入される。
6. 利用規約、プライバシーポリシー、ロゴ、問い合わせ先を準備する。
7. 公開ゲートがすべて揃った後に占いを公開する。
8. AI個別化と週次LINE通知は必要な場合だけ別に有効化する。

## 契約・販売境界

占いパッケージの新規提供可否は、運営団体の契約設定にある`fortunePackageEnabled`で管理する。初期値は無効であり、システム管理者が契約開始後に明示的に有効化する。団体契約が停止中、開始前、終了後の場合も新しいService作成と未導入Serviceへの初回導入を許可しない。

すでに占いパッケージを導入済みのServiceは、契約設定の追加によって停止しない。公開状態、既存結果、運営設定、最新版への安全更新は維持し、新規販売の許可と既存利用の停止を分離する。

## 初期設定

- パッケージキー: `FORTUNE_DAILY_GUIDANCE`
- パッケージ版: `2`
- 対象年齢: 18歳以上
- 結果の保存期間: 90日
- 登録方法: 公開・LINE優先
- 占い公開: 停止
- AI個別化: 停止
- 週次通知: 停止
- 限定公開の参加者上限: 100人

運営画面には、サービスに設定されたパッケージ版、このシステムが提供する最新版、機能の導入状態、更新要否を表示する。サービス側の版がシステムより新しい場合は、互換性を確認できるまで設定変更を控える案内を表示する。

旧版が導入済みの場合は、Service運営者が運営画面から最新版へ更新できる。更新はパッケージ版と不足している無料試験用の契約初期値だけを補い、公開状態、独自解釈、AI、週次通知、参加者上限を含む既存の運営設定を上書きしない。同じ更新を再実行しても追加変更は発生しない。

初回導入と版更新は、対象Service、実行日時、変更前後の版、実行した担当者を監査履歴へ記録する。導入済みパッケージの再実行と最新版に対する更新操作は変更を伴わないため、重複する履歴を作らない。Service運営者は占い管理画面で直近20件を確認できる。履歴には利用者の氏名、選択テーマ、カード、占い結果を保存しない。

## サービス分離

占い専用テンプレートまたは占い設定を持つServiceにだけ占い管理メニューを表示する。投稿支援など別用途のServiceには占い管理を表示しない。

## 再実行時の安全性

導入処理はService管理権限と占いテンプレートをサーバー側で確認する。途中のデータを残さない単一トランザクションで実行し、すでに占い設定が存在する場合は担当や解釈を重複作成しない。導入後も公開、AI個別化、週次通知は停止状態を維持する。

導入時に、既存のService契約設定がなければ無料・100人上限の限定公開設定を作成する。システム管理者がすでに設定した契約条件は上書きしない。既存の占いServiceにも同じ初期設定を補い、運営画面には登録参加者数と残り参加枠を表示する。

参加者上限は共通Service参加基盤で強制する。運営担当者を参加者枠に含めず、同時登録時はService設定行をロックしてから人数を再確認するため、100人を超える登録を許可しない。

## 公開準備

占い管理画面では、次の5項目を順番に表示し、未完了項目から設定画面へ直接移動できる。

1. 占い担当と標準解釈468件
2. ロゴと問い合わせ先
3. 利用規約
4. プライバシーポリシー
5. 公式LINEの接続

公式LINEは、共通LINEを使う場合は稼働中の共通設定、専用LINEを使う場合はテスト利用、有効な接続確認、配信停止の解除を確認する。5項目がすべて揃うまで占いを公開できない。

## 公開後の運用品質

サービス運営者は、直近30日について参加者数、利用者数、占い結果数、AI作成数、標準文表示数、未完了数を集計で確認できる。AI利用時に標準文への切り替えが20%以上なら経過確認、50%以上、失敗率10%以上、または10分以上処理中の結果がある場合は対応が必要と判定する。利用者の氏名と占い内容は運用品質画面へ表示しない。

利用者が結果を実際に開いた時刻を初回だけ記録し、結果作成と閲覧完了を分けて集計する。結果の下には「参考になった」「少し参考になった」「今回は違った」の3択を表示する。「今回は違った」では任意で、あいまい、分かりにくい、不安になった、その他を選べる。自由文と占い本文は評価データへ保存しない。運営者には回答数と理由別件数だけを表示する。

共通Service参加基盤のイベントを利用し、直近30日の新規登録、初回利用、再訪、週次通知の開始・停止、サービス退会を占い運営画面へ表示する。同じ参加者による同種イベントは期間内で1人として集計し、氏名、選択テーマ、占い結果は表示しない。

占いのAI生成は共通のService月間生成枠を利用する。運営画面には当月のService全体の消費数と上限、占い担当の成功・失敗、入出力トークン、概算AI原価を表示する。価格未設定の呼び出しは無料とは扱わず、概算に含まれない件数を明示する。月間上限はシステム管理者が契約設定で管理し、占い運営者は変更しない。

## 週次LINE通知

サービス運営者は、占い公開後に管理画面で配信曜日と時刻を選び、週次LINE通知を有効化できる。通知対象は、年齢確認済みかつサービス参加中で、本人が「週1回のお知らせを受け取る」を有効にした利用者だけとする。

配信時にも、在籍、参加同意、通知同意、LINE接続、友だち状態を再確認する。停止操作が配信準備後に行われた場合も送らない。共有LINEとサービス専用LINEのどちらでも、現在のサービス配信設定に従って送信する。同じサービスから同じ日に複数回送らない。LINE本文には占い結果、選択テーマ、氏名などの個人情報を含めず、サービスを開く案内だけを記載する。

## サービス単位の退会

利用者は占い設定画面から、占いサービスだけを退会できる。実行前に、他のサービスとワタシワークスのアカウントは残り、退会後は占い結果を閲覧できなくなることを表示して再確認する。

退会処理は共通Service参加基盤を利用し、本人の`PARTICIPANT`会員状態だけを`REVOKED`へ変更する。運営担当者の会員状態、共通User、他Serviceの参加、占い結果の保存行は変更しない。退会後は公開中かつ空き枠があるサービスへ再参加でき、再参加時にも最新の利用文書同意と参加者上限を確認する。

## 履歴の閲覧期間

履歴一覧と個別結果は、サービスに設定した保存日数の日本時間の日付だけを表示する。個別結果のURLを保存していても、期間を過ぎた結果は表示、閲覧完了記録、評価の対象にしない。標準設定の90日は当日を含む90日間として計算する。

本番環境では、保護された日次処理がサービスごとの保存日数を確認し、期限を過ぎた占い結果をデータベースから削除する。関連する選択式評価も外部キーの連鎖削除で同時に削除される。日次処理は同じ日に再実行しても、期限切れデータを重複処理しない。
