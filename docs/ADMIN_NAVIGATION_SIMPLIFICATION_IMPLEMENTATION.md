# 本部管理メニュー整理（PR-1A）

作業日：2026-11-03 JST。基準main：`4a856e2d`（監査PR #1447のマージ後）。[実装計画](ADMIN_SIMPLIFICATION_IMPLEMENTATION_PLAN.md)のPR-1Aに対応する。Service/OEMホーム、保存API、承認条件、監査の書込は次の独立PRで扱う。

## 調査と変更

- 既存23リンクを「ダッシュボード」「会員・契約管理」「配信・コンテンツ管理」「サービス設定」「詳細管理」の5分類へ再配置した。URL・既存リンクを削除せず、変更履歴・API接続・権限・法務等を詳細管理へまとめた。
- `/admin`の前方一致で全管理画面にダッシュボードの選択表示が付く問題を修正した。親子のリンクがある場合は最長一致する1件だけを現在位置とする。一般ユーザー画面の親リンクの選択表示は維持した。
- 本部ホームをダッシュボードと明記し、運用通知を先に表示した。会員・問い合わせ・LINE・サービス設定への入口を同画面に追加した。既存の各管理画面に直接進める。
- 公開前チェックの項目・証跡と実行環境・初期設定を閉じたdetailsへ移した。公開判定、必要対応件数、稼働状態、通知は表示を維持した。折りたたみは表示上の整理であり、公開条件や認可を変更しない。
- 本部の文脈をヘッダーに明示し、メニューの操作領域を最低44px、キーボードのフォーカスを可視化した。既存のPCサイドバー・スマートフォンの上部ナビゲーションを再利用した。

## 変更ファイル

- `apps/web/app/ui/app-shell.tsx`：5分類・現在位置の判定・本部表示
- `apps/web/app/(app)/admin/page.tsx`：日常操作の入口と詳細の折りたたみ
- `apps/web/app/styles.css`：操作領域・フォーカス・詳細表示
- `apps/web/test/app-shell.test.ts`：管理トップ・深いURL・最長一致・23リンク保持の検証
- 本報告書

## 設計判断と適用範囲

認可は引き続き各既存ページ/APIが行う。AppShellにロール情報がないため、クライアントで推測した権限によるメニュー削除やアクセス許可は追加しない。新しいナビゲーション基盤・DB・監査レイヤーは作らない。

公開チェックの自動検査・DB取得は従来どおり実行する。このPRでその失敗を無視したり、表示を閉じたことを理由に処理を省略したりしない。非該当集計や通常保存の余分な処理は、計画に従い別PRで解消する。

## 検証

- 対象のVitest：2ファイル6テスト成功。管理トップの誤選択、親子の二重選択、既存リンクの欠落・重複を確認した。
- ローカルe2e：1280px・390px・320pxの3テスト成功。実際のAppShellとCSSを使い、配信分類の自動展開、選択表示1件、詳細管理の開閉、監査画面へのリンク遷移、横はみ出しがないことを確認した。Nextのリンク・画像・pathnameだけをローカルAdapterに置き換えた合成画面であり、DB接続・権限別本番画面の検証ではない。
- 全体検証の最終結果はPR本文に記載する。

## 未解決事項と次の条件

主要業務の実利用頻度、ログイン済み本番での操作時間、ダッシュボードの実データ表示は未測定。23リンクの直接URLと認可処理を維持する一方、全ロールの許可条件を変更する作業は行っていない。

本PRをレビューした後、PR-1BのService/OEMホーム整理、またはPR-2Aの未使用理由入力の撤廃へ進める。本番設定、migration、送信、deploymentは実行していない。
