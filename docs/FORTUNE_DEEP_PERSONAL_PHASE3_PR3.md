# 深層パーソナル占い Phase 3 PR-3

`main` の `e9afbc5b`（#1555）を基点に、鑑定前に本人が入力・確認した項目を、既存のタロット鑑定へ接続した。

## 操作

1. 運営者は「ヒアリングとAI案内役の設定」で、動的ヒアリングと深層鑑定を有効化する。深層鑑定の初期値はOFF。既存のAI鑑定と個別化が有効なServiceで使える。
2. 参加者は「AIと相談を整理してから占う」から回答し、「ここまでで占う」で確認画面を開く。未確認の候補は、本人が採用した場合だけ対象になる。「この内容で占う」で今日の結果を取得する。既存の1日1回のカード・正逆と、同日結果を再利用する。
3. 結果では、本人が確認した相談と大切にしたいこと、カードの承認済み解釈、AIによる状況への当てはめ、考えられる選択肢、今日できる一歩とその理由を区別する。振り返り機能が有効な場合は次回の問いを表示する。

## データと安全性

- `fortune_readings` に生成待ちの確認済み項目 `pending_understanding` と、結果表示用の `deep_reading` を追加した。本人の相談と大切にしたいことは確認済み入力を使い、カードの標準解釈は既存の承認版とカード・正逆・テーマから取得する。
- 確認済み項目は生成・失敗時の復旧・削除・プロフィール更新・退会・期限処理で生成待ちデータから消す。完成した本文と各項目は既存の鑑定結果として本人にだけ表示し、保管期限と削除は既存の鑑定に従う。確認済みの相談項目は、次回の個別化の入力には追加しない。
- 生成には既存のProvider、Quota、原価記録、非同期ジョブを使う。深層鑑定の原価は `fortune-deep-reading-v1` で識別できる。必須項目が欠ける場合や不適切な生成結果は、元のカードの承認済み標準結果に戻す。

## 検証と次の段階

入力の確認状態、構造化出力と不適切な提案の拒否、承認済み標準解釈、再抽選防止、同じカードへのフォールバック、待機データの消去を単体・隔離DBテストで確認する。スマートフォン幅のブラウザテストは、確認・訂正から各鑑定項目の表示まで合成応答で検証する。

PR-4で、本人が許可した情報の次回利用、品質評価と原価分析、隔離環境の統合検証を扱う。実AI評価、本番反映、productionマイグレーション、通知は別途承認の対象。
