# サービス認証・LINE再連携フロー分離

更新日: 2026-09-29。基準: `main` `63483601`。D-143。

## 1. 調査した内容

千ノ国メディアのLINE再連携時に業種選択が出る経路をコードで確認した。専用接続 `/auth/service-line/*` は本人・Workspace・Group・Bunshin・Configurationを再確認し、共通登録を呼ばない。一方、ログイン切れで `/s/:slug/line` またはサービス別アカウントから `/login` に戻ると、戻り先の許可リストがサービス下位ページとアカウントに対応しておらず、サービス情報が消える。LINE Callbackは共通Userプロフィール未完了を理由に `/onboarding` に進め、共通の業種質問を表示していた。

メール認証、法務同意後、ホーム、研修/占い/投稿パートナー画面と管理画面にも同じ問題があった。画像閲覧だけは動画の共通登録除外が適用されていなかった。管理設定・専用LINE・メール・テンプレート・個別化・週次報告の6入口、投稿承認2操作とポイント8操作は戻り先なしで共通ログインへ送っていた。共通登録画面/APIはサービス設定を読みつつ共通Userへ回答を保存する別の混在も含んでいた。

## 2. 変更したファイル

- `apps/web/src/auth/line-return.ts`: サービスページ/アカウントの厳密な復帰許可、共通登録の要否、サービス限定ログインURL。
- `apps/web/app/auth/{line,confirm,email}`、`app/consent/accept`、`src/auth/login-error.ts`: LINE/メール/同意後の統一判定、古いCookie除去、メール送信案内とProvider失敗/認証取消/期限切れ時の再試行画面で戻り先保持。
- `app/onboarding/page.tsx`、`src/http/user-registration.ts`: 旧サービスリンクを戻し、サービス回答の共通Userへの保存を拒否。個人利用の共通登録は維持。
- `src/services/member-service-page.ts`: サービスslugと戻り先が異なる場合は認証/取得前に拒否。
- `app/s/[serviceSlug]/bunshins/[bunshinId]/line/page.tsx`: 未ログインでも元の専用接続画面へ復帰する入口。
- 管理画面6入口、投稿承認/ポイント操作: セッション切れ時のサービス復帰先。
- 認証/復帰・共通登録・サービスページ一覧と既存境界テスト、Decision Log、Roadmap、本報告。

## 3. 主要な設計判断

認証は共通でも、サービスの参加・プロフィール・研修・占い・SNS支援はサービスで判定する。サービス名/slugをハードコードしない。千ノ国の専用参加質問、ハッシーのServiceMemberBusinessProfile（業種含む）、占いの年齢確認、研修のEnrollment、OEMの個別登録を変更しない。初回参加でも当該サービスの参加/招待を通し、共通の事業プロフィールは挟まない。

復帰URLは認可ではない。元のページで本人・有効所属・Workspace/Group・役割を引き続き検証する。外部URL、dot segment、encoded separator、重複Service/紹介query、未知のルート、任意queryは拒否する。共通法務同意は飛ばさない。

## 5. 未解決事項・今回の範囲外

専用LINE再連携の共通Cookie干渉と非公開参加者の接続判定は後続の`docs/SERVICE_LINE_RECONNECTION_ISOLATION_IMPLEMENTATION_REPORT.md`で修正する。共通ログインの試行分離とは別の経路であり、双方の本番反映・実端末検証は区別する。

後続の試行単位分離の実装・有効化条件は`docs/AUTH_RETURN_ATTEMPTS_IMPLEMENTATION_REPORT.md`を参照。以下はこの報告時点の履歴であり、後続実装の本番有効化を意味しない。

- 本番SHA、対象者の実際の遷移、千ノ国の保存設定、公式LINEリッチメニュー/LIFFのリンク、iPhone OAuth復帰は未確認。本番設定を変更した証拠ではない。
- 共通 `/line` は元々サービス指定を持たないプラットフォーム入口である。各公式LINEがここを使っている場合はサービス入口/専用接続へ向ける運用確認が必要。今回リンクの変更・送信はしない。
- 戻り先Cookieはブラウザ単位で有効10分。同時に複数プロジェクトの認証を開始するケース、別ブラウザのメール確認、Cookie期限切れはService情報を保証できない。認証試行ごとに復帰情報を束ねる仕組みは別作業が必要。Cookieは認可に使用せず、データ境界は遷移先で維持する。
- 過去に共通プロフィールへ保存済みのサービス由来情報は移行・削除しない。

## 6. 次へ進める条件

CI確認・マージ・本番反映後、千ノ国の既存参加者でセッション切れ→LINE接続→同意→元サービス復帰を実端末確認する。ハッシー初回だけ必要な業種設定が残ること、占い/研修/OEMと複数サービス参加者で別プロジェクトへ回答・通知先が保存されないことも確認する。残る認証試行単位の復帰・外部リンク検証は別作業として扱う。
