# 誤付与ポイント回収 運用実装レポート

## 1. 調査した内容

- 運営者によるポイント訂正は、利用者の現在残高を超える額を回収できなかった。
- `PointAccount.recoveryDue` と `RECOVERY` 取引種別は存在したが、運営画面・利用者画面・後続付与の処理には接続されていなかった。
- ポイント交換は `recoveryDue = 0` を要求していたため、回収未済額を正しく登録できれば既存の交換防止条件を利用できる。
- 残高照合は利用可能ポイントだけを台帳合計と比較しており、回収未済額を含む正当な負数台帳を扱えなかった。

## 2. 変更したファイル

- `packages/database/src/index.ts`: 回収登録、後続付与による自動充当、誤回収の取消を共通処理として実装した。
- `packages/database/src/point-balance-reconciliation.ts`: 利用可能額から回収未済額を引いた純残高で照合・修復するよう変更した。
- `packages/application/src/point-balance-reconciliation.ts`: 負数の台帳残高を正当な回収未済額として扱えるよう変更した。
- `apps/web/app/s/[serviceSlug]/manage/points/page.tsx`: 運営者の回収・取消操作、回収未済額、監査理由を表示した。
- `apps/web/app/(app)/points/page.tsx`: 利用者へ回収開始・取消・完了と運営者の説明を表示し、未済中だけ交換操作を停止した。
- `apps/web/app/(app)/admin/points/page.tsx`: 管理者照合画面に利用可能額・回収未済額・純残高を表示した。
- `apps/web/src/http/service-reward-export.ts`: 運営CSVに回収未済額、回収、取消の監査履歴を追加した。
- `apps/web/src/services/weekly-progress-report-data.ts`、`weekly-report-line-delivery.ts`: 週次LINEへ回収開始・取消・完了の状態を追加した。
- 関連する単体・境界テストを更新し、回収と自動充当のテストを追加した。

## 3. 主要な設計判断

- 回収取引には運営者が指定した全額を負数で記録する。現在残っている額は即時回収し、不足額だけを `recoveryDue` に積む。
- 以後の付与・返却ポイントは、先に古い回収未済額へ自動充当し、残額だけを利用可能ポイントに加える。
- ポイント口座の不変条件を `利用可能ポイント - 回収未済額 = 台帳合計` とした。利用可能ポイント自体は負数にしない。
- 自動充当は既存の消費リンクで付与取引と回収取引を結び、期限切れや二重利用の計算と整合させた。
- 回収と付与は直列化トランザクションで実行し、同時処理による二重充当を防ぐ。
- 回収理由はサービス監査へ保存し、対象利用者にも表示する。操作IDで再送時の二重回収を防ぐ。
- 取消は元の回収取引を指定して全額を戻す。既に回収した分は利用可能残高へ戻し、未済分は消滅させる。取消操作も操作IDで冪等にした。
- 利用者通知は、ポイント画面では次回表示時に即時確認でき、週次LINEでは個人情報を含めず状態だけを知らせる。

## 4. 実行した検証

- 現在残高を超える回収で、残高が0になり不足分が `recoveryDue` へ記録されること。
- 後続付与が回収未済額へ先に充当され、余剰だけが利用可能になること。
- 同じ操作IDの再送で二重回収されないこと。
- 回収中はポイント交換リンクが表示されず、利用者に理由と残額が表示されること。
- 運営CSVと管理者照合画面が回収未済額を扱えること。
- 一部回収済み・全額未済のどちらでも取消後の純残高が台帳と一致し、同じ取消を再送しても二重返却しないこと。
- 回収開始、取消、完了の案内が利用者画面と週次LINEに表示されること。
- 対象テスト39件、application/database/web の型検査を実行した。

## 5. 未解決事項

- 実運用では、回収・取消理由の記載基準と利用者への問い合わせ対応手順を運営ルールとして定める必要がある。
- LINE通知は週次レポートに含める方式であり、回収操作直後の個別プッシュ配信は無料運用の対象外とした。

## 6. 次Phaseへ進める条件

- CIのテスト・lint・buildが成功すること。
- 本番反映後、運営者がテスト利用者へ「残高を超える回収」を1件登録し、利用者画面の表示、交換停止、次回付与による自動解消、取消による全額復元を確認すること。
