# ワタシワークス公式「毎日の発信アイデア」不足機能調査

## 1. 想定するサービス

店舗、会社、個人事業主が業種と発信目的を登録すると、事業に合ったSNS発信アイデアが毎日LINEへ届く無料サービスとする。

- 千ノ国メディア、副業・アフィリエイト向けサービスとは別Serviceとして作成する。
- 初期MVPは文章中心とし、SNSへの投稿は利用者本人が行う。
- 自動生成とLINE通知を通常導線とし、毎日の生成操作を求めない。
- 運営者は和愛株式会社とする。

## 2. 現在そのまま使える機能

| 領域             | 現状                                                                             |
| ---------------- | -------------------------------------------------------------------------------- |
| サービス分離     | Service、Group、Membership、Knowledge、LINE、Missionをサービス単位で分離できる。 |
| 企業向け初期設定 | 「企業・代理店向け」作成テンプレートがある。                                     |
| 業種選択         | 共通登録画面に業種の選択UIと「その他」の自由入力がある。                         |
| 初回質問         | サービスごとに共通プロフィール項目の表示可否と最大7問の質問を設定できる。        |
| 自動生成         | cron、週間計画準備、Daily Mission生成、再試行、冪等キーがある。                  |
| LINE通知         | 利用者ごとの同意、通知時刻、停止、LINE接続確認、Missionへのリンクがある。        |
| 公式情報         | サービス別Knowledgeを週間計画と投稿案生成へ渡せる。                              |

| 運用確認         | 開始準備、AI失敗、LINE失敗、送信待ち、7日間集計を管理画面で確認できる。          |

## 3. 公開前に必要な不足機能

### P0-1 業種情報をサービス所属単位で保存する

現在の`UserRegistrationProfile`は`userId`で一意であり、業種、会社名、商品・サービスはユーザー共通である。同じユーザーが複数サービスや複数事業へ参加すると、どの事業の情報かを区別できない。

Service Membershipに紐づく企業プロフィールを追加し、最低限次を保存する。

- workspaceId / serviceId / membershipId / userId
- primaryIndustryId / otherIndustryText
- businessName / region / productService
- primaryPurpose / targetAudience
- socialPlatform
- timezone / notificationTime

別Serviceの企業プロフィールをMission生成へ渡さないRepository境界と分離テストを必須にする。

### P0-2 選んだ業種を投稿案生成へ直接接続する

現在、構造化された業種選択は登録プロフィールとLINE一斉配信の絞り込みには使えるが、サービス用Bunshin候補生成、戦略、週間計画、Daily Missionへ明示的に渡されていない。サービス独自の自由回答だけに依存すると、選択した業種と投稿案がずれる可能性がある。

企業プロフィールのスナップショットを次へ渡す。

1. 投稿パートナーの初期設定
2. アカウント戦略
3. 週間計画
4. Daily Mission
5. AI使用記録とPrompt Version

### P0-3 「毎日届く」サービス専用の配信方針を追加する

現在は利用者が週1回、週3回、平日、毎日などの投稿ペースを選び、予定のある日だけ通知する。初期値も週1回である。今回の約束と一致させるには、サービス設定で次を指定できる必要がある。

- 配信頻度: 毎日 / 平日のみ
- 初期通知時刻
- 利用者による時刻変更の可否
- 投稿ペース選択を表示するか
- 配信する内容: アイデアだけ / そのまま使える投稿案

本サービスでは「毎日」を初期値にし、投稿ペースの質問を省略する。

### P0-4 初回導線を短縮する

現在は共通プロフィール、サービス独自質問、投稿パートナー候補の選択、SNSと投稿ペースの設定、自動お届け開始という複数段階がある。無料サービスでは離脱しやすい。

業種、目的、商品・サービス、SNS、通知時刻を一つの導線で保存し、標準の投稿パートナー、Content Pillar、Social Profile、Strategyをバックグラウンドで作る。利用者が明示的に通知同意をした後、自動お届けを開始する。

### P0-5 LINE必須条件を登録画面で明確にする

現在はメールでもサービス参加できるが、自動お届け開始時にはLINE接続と友だち追加が必要である。無料版をLINE配信専用にする場合、参加前にLINE必須と表示し、メールだけで登録した利用者を行き止まりにしない。メール配信も提供する場合は、メール通知ジョブ、停止、重複防止、配信失敗管理を別途追加する。

### P0-6 AI障害時の業種別予備案を用意する

ジョブの再試行と失敗記録はあるが、週間計画またはDaily Mission生成が最終的に失敗すると、その日の案は届かない。無料サービスが「毎日届く」と案内するなら、業種・目的・曜日ごとの審査済み予備案を持ち、AI障害や利用上限到達時に送れるようにする。

予備案にも使用版、業種、目的、配信日、選択理由を記録し、同じ内容の短期重複を避ける。

### P0-7 無料枠の実効上限をサービス単位で適用する

Service Commercial Settingには月間AI生成数などを保存できるが、現在のAI生成制限はWorkspace単位のOrganization Entitlementで判定している。複数Serviceが同じWorkspaceにある場合、千ノ国メディア、副業向け、本サービスの消費量が同じ上限へ集約される。

サービス単位の予約・消費記録を追加し、少なくとも次を制御する。

- 参加者数
- 1人あたりの有効な投稿パートナー数
- 1日あたりの投稿案数
- サービス月間AI生成数と原価上限
- 上限到達時の予備案への切替

### P0-8 公開規模に耐えるSchedulerのページングを追加する

現在のMission Schedulerは、有効な通知設定をID順に最大1,000件取得する。1,000件を超えると常に先頭だけを取得するため、後続利用者が対象にならない可能性がある。Workerも1回5件処理である。

カーソルページング、公平な分割、時刻帯別取得、キュー滞留監視、処理能力試験を追加する。最初の限定テストは現状でも可能だが、一般公開前に対応する。

### P0-9 業種別の安全ルールを追加する

医療・福祉、士業、金融に近い内容などは、一般的な誇大表現防止だけでは不足する。業種ごとに禁止表現、必須注意書き、根拠がない効果・実績の扱い、公開前確認の要否を設定し、生成とQuality Checkの両方へ適用する。

## 4. 初期公開後に追加できる機能

### P1

- 業種マスターの管理画面とサービスごとの表示業種設定
- 不動産、宿泊・観光、製造、IT・SaaS、コンサル、フィットネス、自動車、農林水産などの追加
- 業種別テンプレート、季節行事、地域情報の管理
- 配信アイデアの「使う・違う・投稿した」フィードバック
- 業種別の登録完了率、通知成功率、閲覧率、7日・30日継続率、1人あたり原価
- 長期休止、曜日指定、祝日除外
- 複数店舗、複数SNS、複数担当者

### P2

- 有料プランへの移行
- 画像生成、投稿予約、成果分析
- メール配信
- 業種別の承認ワークフロー

## 5. 推奨MVP

最初は100人以下の限定公開とし、次に絞る。

- LINEログインと友だち追加を必須にする。
- InstagramまたはXのどちらか1つを選ぶ。
- 毎朝8時を初期値とし、7時から20時59分の範囲で変更可能にする。
- 1日1件、文章中心の投稿アイデアを送る。
- 画像生成、動画生成、自動投稿は提供しない。
- 業種、目的、商品・サービス、対象顧客を生成へ必ず渡す。
- AI障害・上限到達時は審査済み予備案を送る。
- サービスを非公開で作り、運営者5人、一般参加者10人の順で受信テストする。

## 6. 実装順

1. Service Membership単位の企業プロフィールと分離テスト
2. 企業プロフィールを戦略・週間計画・Daily Missionへ接続
3. Service Delivery Policyと毎日配信専用の初回導線
4. 業種別予備案と障害時フォールバック
5. サービス単位のAI利用上限・原価上限
6. Schedulerページングとキュー監視
7. 業種別安全ルール
8. 管理画面の業種別KPI
9. 限定公開と実受信テスト

## 7. 公開条件

- 別Service、別Membershipの企業プロフィールとMissionが混ざらない。
- 初回設定後、利用者操作なしで7日連続の対象日に1件ずつ生成・配信される。
- 重複生成、重複通知がない。
- 通知停止、退会、LINEブロック、Service停止が配信時にも反映される。
- AI障害と利用上限到達時にも審査済み予備案へ切り替わる。
- 運営画面で失敗、滞留、原価、配信成功率を確認できる。
- 利用規約、プライバシーポリシー、問い合わせ先、LINE表示文言を公開済みにする。
