## 3. 主要な設計判断

### 最初に提供する情報（設計案・未実装）

接続許可は一つのWorkspace/Service/Membership/User/Bunshinに固定する。別Bunshinは別許可を要する。

| 読取用途         | 最小データ                                       | 制限の初期案                                                  |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------- |
| 今日のミッション | 日付・状態・形式・所要時間・本人向け手順         | 保存済みのみ、今日のJST範囲、最大10件                         |
| 投稿案           | 本人が確認可能な保存済みテキスト・形式・採否状態 | 最大10件、明示選択した対象のみ。raw JSON/生成promptを返さない |
| 利用状況         | 7日/30日の生成・採否・自己申告投稿・活動日数     | 原価、被紹介者、管理情報、scope内部IDを返さない               |

日付・期間はサーバーで検証する。新規生成、閲覧イベント記録、画像署名URL発行、LINE/SNS送信をreadに隠さない。投稿完了報告は公開の証明ではない。本文は外部入力として扱い、本文中の命令でtool権限を広げない。

件数・期間はPoC内の仮上限であり、既存会員機能の利用を制限しない。外部送信には明示同意が必要。Memory、Knowledge、企業情報、メール、LINE識別子、token、生成内部情報を初回対象にしない。

### 認可と停止

外部認証の具体方式は実機互換確認後に決定する。OAuthを採用する場合は標準ライブラリ/既存認証基盤の適合を比較し、独自OAuth serverを急造しない。共有APIキーを全会員の代理に使わない。

サーバーが接続主体からscopeを解決し、リクエスト本文のuser/workspaceを信用しない。実行ごとにgrant有効期限・失効・環境・read scope・現時点の本人/参加/所有/Capability/機能停止を照合する。読取後にも失効と所有権を再確認し、変更中は結果を返さない。認可失敗を空データの成功に変換しない。

接続解除はサーバー側grantを失効させる。外部側の接続解除だけに依存しない。本文やsecretを含まない監査に、実行者・接続識別子・操作・成否・件数・遅延・契約versionを記録する。短いtimeout、件数/サイズ上限、接続・利用者単位rate limit、停止スイッチを実装時の必須条件にする。

## 4. 実行した検証とPoC合格条件

本PRは文書と公式一次情報・既存コードの照合のみ。実接続・OAuth・tenant分離のPoCを実施済みとは扱わない。文書formatとdiffを検査し、PRの標準CI結果を別途記録する。

次の試験は合成データと独立テスト環境でCI再現可能にする。

| 試験         | 合格条件                                                                    |
| ------------ | --------------------------------------------------------------------------- |
| 本人の3読取  | 許可されたデータだけ。既存Read Modelと数値一致、二重集計なし                |
| 越境         | 別User/Workspace/Service/Membership/Bunshinの列挙・直接指定・ID差替えを拒否 |
| 権限変化     | grant失効/期限切れ、退会、所有変更、Capability停止、全体停止後は拒否        |
| 読取中の解除 | 応答前の再確認でデータを返さない                                            |
| 入力         | 余分なfield、無制限期間、未知tool、過大件数、任意URL/SQLを拒否              |
| 書込遮断     | 採否・生成・SNS投稿・設定変更を拒否し、原本が不変                           |
| 障害         | timeout/rate limit/保存先障害を固定分類で返し、無限再試行・本文logなし      |
| 副作用       | readでMissionActivity/通知/AI課金を発生させない                             |
| 日付         | JST日付境界と7/30日窓、旧データの欠損を検証                                 |
| Muse実機     | テスト本人のみ接続でき、読取・拒否・サーバー解除が再現可能                  |
