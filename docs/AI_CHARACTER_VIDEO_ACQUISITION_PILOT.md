# AIキャラクター動画 登録獲得実証・実装計画

## 1. 目的

AIキャラクター動画を使い、ワタシワークスの個別サービスへの登録、初回利用、初回投稿、7日継続までを実証する。

再生数だけを成功条件にしない。動画を入口として、利用者がサービス内で実際に行動を開始し、継続したかを評価する。

最初は自社運営の限定サービスで実証する。成果が確認できる前に一般ユーザー向け標準機能として公開しない。

## 汎用プログラム基盤としての位置づけ

本機能をAI女性キャラクター、ダンス、副業へ固定しない。ワタシワークスの共通機能を組み合わせた「実践プログラム」を作成し、対象サービスへ提供できる基盤とする。

構造を次のように分離する。

1. 共通機能: AIキャラクター、画像、動画、台本、Prompt、Mission、LINE、実績
2. Program Template: 再利用可能な内容・進行・ゴール・安全ルールの原型
3. Service Program: 個別サービスが採用し、ブランド・素材・提供条件を設定した版
4. Program Offering: 無料・有料、期間、上限、販売・原価・サポート責任を示す提供条件
5. Program Enrollment: 利用者が選んだ支援方法・ゴール・開始時点の条件

第一号は「AI女性キャラクターのダンス動画を使い、SNS収益化を目指す実践プログラム」とする。表示では収益を保証せず、投稿・計測・改善を行うプログラムとして説明する。

同じ基盤で、商品紹介、顔出しなし解説、店舗集客、企業アンバサダー、採用、地域活動等のプログラムを追加できるようにする。

## 2. 採用する提供方式

利用者はサービス内で、必要な支援方法を選べる。

### 作り方を受け取る

既存の`GUIDED`を利用する。

- 今日の企画
- 台本
- 画像生成Prompt
- 動画生成Prompt
- 推奨ツールと作業手順
- 投稿文、ハッシュタグ、AI・広告表記
- 利用者専用URL
- 完成例

動画生成と編集は利用者が外部ツールで行い、SNS投稿は本人が手動で行う。

### 完成品を受け取る

既存の`READY_TO_USE`を利用する。

- 運営が確認した完成動画
- 媒体別の投稿文
- ハッシュタグ、AI・広告表記
- 利用者専用URL
- 採用、不採用、ダウンロード、投稿完了、投稿URL

初期実証では運営が完成動画を作成・確認して利用者へ割り当てる。Kling等の生成AI動画Providerをワタシワークスから自動実行する機能は後続判断とする。

### 企画だけ受け取る

既存の`IDEA_ONLY`を維持し、経験者向けに企画と検証意図だけを提供できる。

支援方法はサービスで利用可否を設定し、利用者が選択・変更できる。変更履歴を残し、過去のMissionや動画の提供条件を上書きしない。

## 3. 利用者別ゴール

ゴールはサービス全体へ固定せず、利用者ごとに設定する。完全な自由入力だけにはせず、サービス管理者が用意した候補と任意の補足を組み合わせる。

### 行動目標

- 初めて投稿する
- 7日間継続する
- 週に指定回数投稿する
- 動画制作を習得する

### 集客目標

- プロフィール遷移を増やす
- サービス登録を増やす
- LINE連携を増やす
- 問い合わせを増やす

### 事業目標

- 商品紹介を行う
- 購入につなげる
- 売上目標へ近づく

利用者は目標値、期限、投稿頻度、対象者、任意の説明を保存できる。数値目標を持たない場合は行動目標だけでも開始できる。

事業成果は外部システムの数値を正とし、ワタシワークスは売上や成果を保証しない。

## 4. ゴールを生成へ反映する境界

利用者のACTIVEなゴールだけを、同じサービス・同じ利用者の週間計画とDaily Missionへ渡す。

- 行動目標では、短時間で完了できる企画と継続性を優先する。
- 視聴目標では、冒頭、視聴維持、保存価値を優先する。
- 登録目標では、利用実演、LP、CTAを優先する。
- LINE目標では、無料特典、連携後の体験、再訪を優先する。
- 商品目標では、承認済み商品情報、必須表記、禁止表現、専用URLを適用する。

別サービス、別利用者、終了済みゴールを生成へ渡さない。ゴール文を信頼された命令として扱わず、入力データとして扱う。

## 5. 完成動画配布

完成動画はサービス管理者が登録・確認し、対象利用者へ明示的に割り当てる。

最低限保持する情報:

- service、workspace
- 元となるVideo Project / Render
- 配布版と状態
- 対象SNS
- AI表示・広告表示Snapshot
- 利用可能期間
- 最大配布数
- 割当先Membership
- 割当日時、確認者
- 採用、不採用、ダウンロード、投稿完了
- 投稿URL

同じ動画の無制限配布を避ける。利用者別に字幕、CTA、投稿文、専用URLなどを変更できる構造にする。

完成動画の割当は、動画の所有権や利用許諾を譲渡する処理ではない。利用範囲、再配布、利用期限、契約終了後の扱いを別途明示する。

## 6. 登録経路と実績

外部成果計測URLと、ワタシワークスへの登録経路を分離する。

登録経路には推測困難なCodeを使用し、次を結び付ける。

- service
- SNS媒体
- 動画・投稿案
- 企画形式（美女・共感・実演）
- 投稿者Membership
- LP訪問
- 登録
- オンボーディング完了
- 初回Mission確認
- 初回投稿
- D7活動

URLへ氏名、メールアドレス、LINE user ID等を含めない。クリック、外部購入、報酬計算、支払いは本機能で行わない。

SNS側の再生、保存、コメント、プロフィール遷移は初期段階では手動入力とし、取得元、取得日時、対象期間を保存する。

## 7. KPI定義

- 登録率 = 登録者数 / LP訪問者数
- オンボーディング完了率 = 完了者数 / 登録者数
- 初回Mission確認率 = 確認者数 / 登録者数
- 初回投稿完了率 = 投稿完了者数 / 登録者数
- D7継続率 = D7判定日に活動した人数 / D7判定対象者数

少数の偶然を成功と判定しない。各判定には最低母数を設定し、未達の場合は成功・失敗ではなく`INSUFFICIENT_DATA`とする。

Preference（採用、不採用、本人らしさ）とOutcome（投稿、登録、継続）を分離する。登録経路Codeから確認できない因果関係をAIが断定しない。

## 8. データ構造候補

### ProgramTemplate / ProgramTemplateVersion

プラットフォームまたは許可されたサービス運営者が作る再利用可能な原型を保持する。

- 名称、説明、カテゴリー、対象者
- 標準期間、Mission構成、ゴール候補
- 対応する支援方法、動画・投稿Template
- AIキャラクター要件
- 必須表記、禁止表現、安全ルール
- 標準上限
- 所有者、状態、Version、公開範囲

原型の更新で提供中の内容を上書きせず、採用Versionを固定する。

### ServiceProgram

サービスが採用したProgram Template Versionと、サービス固有の表示名、Brand、素材、商品、LINE、期間、機能設定を保持する。他サービスへ自動共有しない。

### ProgramOffering

販売・提供条件をSnapshot可能な形で保持する。

- seller: 販売者
- priceOwner: 価格決定者
- paymentOwner: 売上受取責任者
- apiCostOwner: AI原価負担者
- supportOwner: 問い合わせ対応者
- contentOwner: 台本・素材の所有者
- characterOwner: AIキャラクター所有者
- 無料・有料、価格参照、利用期間、座席、生成上限、再生成上限

AVの初期実証では無料・手動参加だけを扱う。Checkout、請求、返金、売上分配、代理店報酬は販売プランPhaseで実装する。

### ProgramEnrollment

Service MembershipとService Programを結び、開始・終了、選択した支援方法、Goal、利用権、参加時点のOffering Versionを保持する。契約条件や過去の進捗を後の設定変更で上書きしない。

### ServiceSupportPolicy

サービスで利用可能な`IDEA_ONLY / GUIDED / READY_TO_USE`、初期値、変更可否を保持する。

### ServiceMemberSupportPreference

利用者の現在の支援方法と変更日時を保持する。履歴はEventまたはAuditへ残す。

### ServiceGoalDefinition

サービス管理者が用意するゴール候補、分類、計測単位、入力可否、状態、Versionを保持する。

### ServiceMemberGoal

利用者のゴール、目標値、期限、投稿頻度、対象者、任意説明、状態を保持する。ACTIVEは用途ごとの上限を定める。

### AcquisitionExperiment / ContentVariant

7日・30日の実証期間、対象SNS、企画形式、目標、判定基準、コンテンツとの関係を保持する。

### AcquisitionSource / FunnelEvent

登録経路Codeと、サービス内で発生した登録後の行動を保持する。冪等Keyで重複計上を防ぐ。

### VideoDistribution / VideoAssignment

確認済み完成動画の配布条件と利用者割当を保持する。

既存`PostRecord.manualMetrics`へ実証全体の集計値を詰め込まず、計測定義と履歴を持つ独立Resourceにする。

## 9. 権限

### プラットフォーム管理者

- Pilot機能の利用許可
- 原価上限、緊急停止、全サービス監査

### サービス所有者・運営管理者

- 支援方法の利用可否
- ゴール候補
- 実証プロジェクト
- 完成動画の登録、確認、停止、割当
- サービス内の集計結果

### コンテンツ担当者

- 台本・動画候補の作成
- 権限が与えられた範囲の完成動画準備
- 個人目標や個人行動の横断閲覧は許可しない

### 一般利用者

- 自分の支援方法とゴール
- 自分に割り当てられた動画
- 自分の投稿・実績

すべてのRepositoryで`workspaceId + serviceId + serviceMembershipId`を再検証する。

## 10. 実装Phase

### AV-0: Rebaseline

本書、Decision Log、Roadmapを更新する。コード、Schema、Migrationは変更しない。

### AV-1: Program Core

Program Template / Version、Service Program、Offering、Enrollment、所有・販売・原価・サポート責任、Version、Audit、Isolation Testを実装する。決済は接続しない。

### AV-2: Program管理API/UI

プラットフォーム管理者の公式Program作成、対象サービスへの提供、サービス管理者の採用・設定、利用者の参加を接続する。初期は無料・招待限定・手動Enrollmentとする。

### AV-3: 支援方法・ゴールCore/API/UI

サービス管理画面と利用者初回設定へ接続し、週間計画・Daily Missionの安全なContextへ反映する。

### AV-4: 汎用AIキャラクターCore/API/UI

個人、サービス公式、プラットフォーム公式のAI Character Profile、基準画像、外見・世界観・Prompt、利用許諾、安全ルール、Versionを動画生成機能へ接続する。「美女」は設定例とし、固定Enumにしない。

### AV-5: 完成動画配布Core

確認済みRenderのDistribution、Assignment、配布上限、期限、停止、利用権Snapshot、Isolation Testを実装する。

### AV-6: 完成動画配布API/UI

管理者の登録・割当と、利用者の確認、採用、不採用、ダウンロード、投稿完了を接続する。

### AV-7: 登録経路・Funnel Event

媒体・動画・利用者別のSource Code、登録、オンボーディング、Mission、投稿、D7 Eventを冪等に接続する。

### AV-8: 実証プロジェクト・比較

美女・共感・実演のVariant、最低母数、7日・30日判定、手動SNS実績、比較画面を実装する。

### AV-9: 週次改善

前週実績から一つだけ改善項目を提案する。AI出力だけで設定を自動変更せず、管理者または利用者が確認する。

### AV-10: 限定モニター

Feature Flagで対象サービスと参加者を限定し、原価、所要時間、投稿率、D7継続を検証する。

## 11. 初期範囲外

- SNS OAuth、自動投稿、コメント自動返信
- Kling等の生成AI動画Providerの自動実行
- 成果報酬計算、支払い、顧客情報管理
- AIによる成果保証、成功・因果関係の断定
- 同じ完成動画の無制限配布
- 一般サービスへの自動開放
- 複数サービス間での目標・実績・動画割当の共有
- Checkout、請求、返金、売上分配、代理店報酬

## 12. 受入条件

- サービスが利用可能な支援方法を設定できる。
- プラットフォームまたは許可されたサービス運営者が汎用ProgramをVersion管理できる。
- サービスがProgramを採用し、他サービスと分離して提供できる。
- Programの所有者、販売者、価格決定者、原価負担者、サポート担当を区別できる。
- 利用者が自分の支援方法とゴールを選択・変更できる。
- ゴールが同じ利用者・サービスの計画とMissionだけへ反映される。
- 管理者が確認済み完成動画を対象利用者へ割り当てられる。
- 利用者が完成動画を確認し、投稿完了まで記録できる。
- 作り方コースでは台本・Prompt・手順を受け取れる。
- 登録経路と登録後行動を動画・媒体・投稿者別に集計できる。
- 最低母数未達を成功と判定しない。
- 他サービス・他利用者のゴール、動画、実績が混入しない。
- SNS投稿は本人が手動で行う。

## 13. 停止条件

各Phaseを独立PRにする。AV-0のレビュー後にAV-1へ進む。

AV-1着手前に、Programを作成できる役割、公式Templateの公開範囲、所有・販売・価格・原価・サポート責任を人間確認する。AV-3着手前に、支援方法の初期値、自由ゴールの許可範囲、同時ACTIVE Goal上限を確認する。AV-5着手前に、完成動画の利用規約、最大配布数、利用期限、原価負担者を確認する。AV-7着手前に、Cookie・同意・保持期間・登録経路のプライバシー方針を確認する。
