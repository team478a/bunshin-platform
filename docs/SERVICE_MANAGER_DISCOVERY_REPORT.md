# サービス運営画面への入口 改善レポート

## 1. 調査した内容

- 本番のLINE利用者は千ノ国メディアのサービス管理者として設定済みだった。
- プラットフォーム管理者ではないため、`/admin` が404になるのは権限境界どおりだった。
- 運営団体の所有者ではないため、アカウント画面の運営者メニューと運営団体一覧には入口が表示されなかった。
- 参加中サービス一覧には管理可能と表示されるが、サービス運営画面へのリンクがなかった。

## 2. 変更したファイル

- `apps/web/app/(app)/groups/page.tsx`: サービス管理者へ運営画面の入口を表示する。
- `apps/web/app/(app)/account/page.tsx`: 運営団体の所有権がなくても、管理できるサービスを運営者メニューへ表示する。
- `apps/web/test/service-manager-entry-boundary.test.ts`: 2つの入口とサービス管理権限の境界を検証する。
- `docs/REMAINING_FEATURE_IMPLEMENTATION_PLAN.md`: 無料運用の開始導線を更新する。

## 3. 主要な設計判断

- サービスの `SERVICE_OWNER` または `SERVICE_ADMIN` だけに入口を表示する。
- URLは公開サービスのslugから組み立て、既存のサービス管理画面でも同じ権限を再検証する。
- プラットフォーム管理者や運営団体管理者の権限を追加しない。
- 既存のグループ管理機能は残し、無料運用に必要なサービス全体の管理画面を先頭に表示する。

## 4. 実行した検証

- サービスだけを管理する利用者に2つの入口が表示されることを自動テストで確認した。
- 対象テスト7件、Web型検査、全体テスト19タスク、lint 19タスク、production build 10タスクをすべて完了した。

## 5. 未解決事項

- 本番反映後、LINE利用者の参加中サービス一覧またはアカウント画面から運営画面を開く必要がある。
- 4週間の開始操作は、運営画面の「ポイントとバッジ」で行う。

## 6. 次Phaseへ進める条件

- 本番で「サービス運営画面を開く」が表示される。
- 千ノ国メディアの運営画面とポイント管理画面が404にならず開く。
- 4週間の期間と試験利用者を保存し、開始確認5項目を確認できる。
