# 運用管理・復旧Runbook

更新日: 2026-08-24  
対象: BUNSHIN Platform管理者

## 1. 毎日の確認

1. Productionの`/admin`を開く
2. 「いまの運用状態」を確認する
3. 「対応が必要」が0件であることを確認する
4. 「確認」がある場合は案内先を開き、意図した停止や再実行待ちか確認する

画面は次を一括確認する。

- 使用中OpenAI設定、全体停止、接続確認
- 使用中LINE設定、全体停止、接続確認
- LINE配信失敗、再実行待ち、再実行不能
- 公開中LINEリッチメニュー
- 暗号化親鍵、定期処理鍵、非公開画像保存設定の登録有無

秘密値そのものは表示しない。

## 2. AI生成障害

1. `/admin/ai`でOpenAIの使用中設定を確認する
2. 全体停止、接続確認日時、最終エラー、日次・月次予算を確認する
3. APIキーが無効な場合は新しい設定版へ登録する
4. 接続テストを実行する
5. 成功後、SUPER_ADMINが理由を入力して使用中へ切り替える

旧設定を直接上書きしない。APIキーをチャット、Issue、ログへ貼らない。

## 3. LINE通知障害

1. `/admin/line`で使用中設定と接続確認を確認する
2. 全体停止とQuota状態を確認する
3. 失敗分類、再実行待ち、再実行不能を確認する
4. 認証エラーなら新しい設定版へSecret・Tokenを登録する
5. 接続テスト成功後に使用中へ切り替える
6. 一時障害だけを再実行する

同じ通知の重複送信を避けるため、失敗分類を確認せず再実行しない。

## 4. LINEリッチメニュー障害

1. 使用中LINE設定が確認済みであることを確認する
2. LINE全体停止中でないことを確認する
3. 対象メニューの画像と固定4リンクを確認する
4. 下書きまたはエラー状態を確認済みにする
5. Production確認と理由入力後に公開する

公開処理は環境・内部ID・versionにより同じLINEメニューを再利用する。タイムアウト時は画面を確認し、公開状態が更新されていない場合に再試行する。

## 5. 緊急停止

漏えい、誤配信、異常原価が疑われる場合は復旧より停止を優先する。

1. LINE通知またはAIを全体停止する
2. 発生時刻、対象環境、影響範囲、操作者、停止理由を記録する
3. Provider Credentialが関係する場合はProvider側で失効する
4. 新しいCredentialを新しい設定版へ登録する
5. 接続テストを行う
6. 人間が影響と安全性を確認する
7. SUPER_ADMINが新しい版へ切り替える

## 6. 管理画面へ移さない設定

次はApplication起動と安全境界に必要なため、管理画面から変更しない。

- `DATABASE_URL`
- `DIRECT_URL`
- `SESSION_SECRET`
- `CRON_SECRET`
- `ENCRYPTION_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- Vercel認証情報
- Deep Link署名の親鍵

これらが不足した場合、管理画面は値を表示せず「設定が必要」とだけ表示する。

## 7. Production確認

Production変更では必ず次を満たす。

- 対象環境が`PRODUCTION`
- 変更理由を入力した
- 接続テストが成功した
- Preview／StagingのCredentialやURLを使っていない
- 変更後に主要導線をスマートフォンで確認した
- 問題時に戻す旧versionを確認した
