# ハッシーのメールログイン切り分け

更新: 2026-10-25

## 今回の症状

ハッシーの参加入口からメール登録を行ったあと、メール本文には `[BUNSHIN]` と表示され、確認画面が「ワタシワークスへログイン」になります。認証後はログイン済みでも、ハッシーを利用できない画面が表示されます。

この症状は一つの原因ではありません。次の二つを分けて確認します。

1. Supabase Authのメールテンプレートがサービスの戻り先を引き継いでいるか。
2. 本番DBでハッシーが公開サービスとして解決でき、メール利用者の参加登録を受け付ける設定になっているか。

## コードで直した範囲

認証済みなのにハッシーのサービス設定を解決できない場合、画面を「LINEからのご利用」と表示しないようにしました。ハッシーの名前を表示し、次を明示します。

- 認証自体は完了している
- メールとLINEは別の認証方法である
- ハッシーの公開設定または参加登録を運営者が確認する必要がある
- 何度もログインし直す必要はない

サービス名は明示的な許可リストからだけ表示します。サービスの存在や参加状態を推測して他サービスへ流用することはありません。

## 本番設定で確認する項目

本番の `/s/hassy` が実際の参加案内を表示するには、サービス基盤の設定が必要です。管理画面または安全な運用手順で、ハッシーについて次を確認してください。

- サービスの公開状態が `PUBLIC`
- 所属グループとWorkspaceが `ACTIVE`
- 公開開始日時・終了日時が現在時刻を含む
- 新規登録方式が `PUBLIC`（テスト運用で承認を不要にする場合）
- メールログインが有効
- 招待コードが不要な設定
- 必要な利用者上限が設定されている

この設定が未完了のままでは、ログイン成功後も参加登録を作成できません。メールを再送しても直りません。

## Supabase Authメールテンプレート

メール本文と件名の `[BUNSHIN]` はアプリ画面ではなく、Supabase Authのメールテンプレートです。最低限、確認リンクは固定のSite URLではなく `{{ .ConfirmationURL }}` を使う必要があります。これにより、アプリが渡した `returnTo=/s/hassy...` が確認画面まで保持されます。

例（サービス名を固定表示しない共通テンプレート）:

```html
<h2>サービスへログイン</h2>
<p>ご利用中のサービスにログインするためのリンクです。</p>
<p><a href="{{ .ConfirmationURL }}">ログインする</a></p>
```

現在のアプリは `returnTo` から確認画面をハッシー専用表示へ切り替えられます。ただし、Supabaseの標準テンプレートだけでは、同じテンプレートの件名・本文へリクエストごとのサービス名を安全に差し込めません。

サービスごとに「ハッシーへログイン」のような件名・本文を動的に送るには、Supabase Send Email Hookと認証済みのメール送信Provider（またはサービスごとの別テンプレート）が必要です。ユーザーmetadataへサービス名を保存してテンプレートで表示する方法は、UserとServiceを混在させるため採用しません。

## 残っている作業

1. Supabaseのメールテンプレートを `{{ .ConfirmationURL }}` 方式へ更新する。
2. 本番のハッシー公開設定・参加登録設定を確認する。
3. 必要であれば、別タスクとしてSend Email Hookを設計・承認し、サービス別件名・本文を実装する。

テンプレート変更と本番DB設定は外部サービスの変更を伴うため、コード変更のマージだけでは完了しません。
