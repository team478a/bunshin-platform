# サービス参加者への投稿案の自動お届け

2026-09-06 の利用者指摘に基づく仕様修正。初回設定後は投稿案が自動で届き、利用者は確認・コピー・SNSへの投稿だけを行う。毎日の生成操作や週間予定の確定を求めない。

- 初回にSNS・投稿ペースとLINE受け取り時刻を設定する。受け取り開始ボタンに通知への同意を明示する。既存利用者の通知同意を勝手に作成しない。
- 保存後は週間準備を既存ジョブへ登録する。画面を閉じても処理を続ける。
- 既存の毎分cronが指定時刻に日次ジョブを登録する。サービス所属の本人について、日次処理が今週の予定を作成・確定し、予定のある日だけ投稿案生成とLINE配信ジョブ登録を行う。日曜は翌週も準備する。予定のない日は正常終了する。
- 個人用の週間予定の手動確定は従来どおり。サービスの自動処理には公式知識とサービススコープを渡し、個人知識・Memoryを混ぜない。
- 通知停止、参加取消、Workspace変更を処理時にも検証する。LINE配信の所属はBunshinから決定し、通知からサービス画面を開く。
- 同じ日・週のジョブキー、生成の既存結果再利用、配信キーにより重複生成・重複配信を抑止する。Provider障害は既存ワーカーの再試行と失敗記録を使用する。

運用条件: 本番cron/workerの稼働、検証済みのLINEチャネル、利用者のLINE接続と友だち追加が必要。設定済みでも本番での実際の受信まで確認したことにはならない。受け取り時刻は生成・配信にかかる時間の分だけ前後する。最初のお届けは選んだペースの次の投稿予定日となる。

検証: 日次ジョブから週間準備・自動確定・安全な生成・配信キューまでの連携、予定のない日、翌週、停止・権限失効、生成失敗、サービスへの通知リンク、ORGANIZATION/MEMBERのDB権限境界を回帰テストする。
