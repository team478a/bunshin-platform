# 無料運用向けポイント・バッジ自動反映

更新日: 2026-09-11

## 調査した内容

- ポイント台帳、初期付与ルール、利用者向け残高画面は実装済みだった。
- 共通バッジの判定、進捗、獲得、利用者向け画面も実装済みだった。
- ただし、ポイント付与処理と共通バッジ判定は定期処理から呼ばれていなかった。
- 共通バッジ10種類はコード上に定義されていたが、本番DBへ自動登録するmigrationがなかった。

このため、画面を開けても利用者の行動がポイントやバッジへ自動反映されない状態だった。

## 変更したファイル

- `apps/web/src/http/mission-scheduler.ts`
- `apps/web/test/mission-scheduler.test.ts`
- `apps/web/app/(app)/points/page.tsx`
- `packages/database/prisma/migrations/20260911090000_seed_common_badges/migration.sql`

## 主要な設計判断

- 既存の毎分Schedulerへポイントとバッジの処理を接続し、追加のCronを増やさない。
- 1回50件に制限し、未処理の過去行動も毎分順番に追いつくようにする。
- ポイント・バッジ処理の障害で、今日の企画生成など既存の無料機能を止めない。
- 初期共通バッジはmigrationで登録し、管理者による初回手作業を不要にする。
- バッジの公開範囲は従来どおり初期非公開とする。
- ポイント画面の週間ルール表示キーをDBの正しいキーへ合わせる。
