# ワタシワークス プラットフォーム管理者マニュアル

プラットフォーム管理者はワタシワークス全体を管理します。日々のサービス運用は、原則としてサービス管理者へ委任してください。

## 初期設定の順番

1. `/admin/services` でサービスを作成します。
2. サービス名、ロゴ、色、登録方式、利用規約、プライバシーポリシーを登録します。
3. サービスの運営者を追加し、サービス管理者の役割を付与します。
4. 必要に応じてサービス専用LINE、AI、画像、動画の設定を行います。
5. 接続確認に成功した設定だけを有効にします。
6. 少数のテスト参加者で、登録→投稿案→承認→投稿完了→通知まで確認します。

## 管理画面の主な役割

| 画面               | すること                                           |
| ------------------ | -------------------------------------------------- |
| サービス管理       | サービス作成、停止、販売プラン、独自ドメインの準備 |
| APIキーと接続確認  | AI・検索・メール等の設定保存、接続確認、有効化     |
| LINE運用           | 共通LINE設定、リッチメニュー、配信状況、障害確認   |
| ユーザーと利用状況 | 全体の利用状況、異常確認                           |
| 運用レポート       | 投稿・生成・配信などの全体傾向確認                 |
| 運用通知           | 今すぐ対応する障害や未設定の確認                   |
| 変更履歴           | 設定変更と実行者の確認                             |
| 法務文書・退会要求 | 規約、同意、退会・削除要求の対応                   |

## 秘密情報の扱い

- APIキー、LINE Channel Secret、Access Token、DB接続情報、署名鍵は画面・CSV・監査ログへ平文で残しません。
- 保存済みの秘密情報は「登録済み」や末尾マスクで確認します。
- 値を変更するときは、目的・対象サービス・影響範囲を確認し、変更理由を残します。
- 本番用の秘密情報を開発・検証環境へコピーしません。

## サービスの販売プラン

サービス管理の「販売プラン・契約上限」で、月額、人数、AI・画像・動画の契約上限を記録できます。

- これは契約上の管理情報です。実際に利用できる機能や回数は、サービス内の機能設定が正です。
- カード情報、請求書発行、決済代行のAPI連携はこの画面では行いません。
- 有料化する前に、利用量・原価・問い合わせ量を運用レポートで確認します。

## OEM・独自ドメイン

「OEM・独自ドメインを準備する」では、使用予定のドメインと確認状態を記録します。

1. `app.example.jp` のようにホスト名だけを登録し、準備中にします。
2. DNSとホスティング側の設定を行います。
3. 接続を確認してから確認済みにします。
4. 実際にサービス画面が開くことを確認してから利用中にします。

この画面はDNSやVercelを自動変更しません。独自ドメインでの実ルーティングは別途ホスティング設定が必要です。

## 障害時の優先順位

1. 運用通知で影響範囲を確認します。
2. LINE・AI・画像・動画の利用中設定を必要なら停止します。
3. 秘密情報を画面・ログ・問い合わせ本文に貼り付けません。
4. 変更履歴と接続確認結果を確認します。
5. 復旧後は少量のテストで確認してから再開します。

## 本番開始前チェック

- 本番のサービス名・規約・問い合わせ先が正しい
- サービス管理者の権限が最小限である
- 利用するLINE・AI・メール設定が「確認済み」である
- 配信停止と通知の導線が確認できる
- 画像・動画の利用回数と予算上限が設定されている
- 退会・削除要求を受ける窓口が決まっている
- バックアップと監査ログの確認手順が決まっている
