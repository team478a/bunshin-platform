# 本人の商品プロフィール保存・再利用 実装レポート

## 調査内容

前段で、運営者確認済みの本人URLからPR表記付き投稿文を作れるようにした。一方、商品名・伝えたいポイント・対象者は毎回入力が必要で、端末をまたいだ再利用ができなかった。

## 変更内容

- `MemberProductProfile`を追加し、商品情報をサービス参加者単位で保存する。
- 投稿文作成画面に「保存した商品」と「新しい商品を登録」を追加する。
- 保存済み商品を選ぶと、URL、商品名、伝えたいポイント、対象者をフォームへ復元する。
- 投稿文作成時に商品情報を作成または更新する。
- 保存・取得APIでは、現在の利用者とサービスをサーバー側で決定する。

## 主要な設計判断

- 商品プロフィールはWorkspace、Service、Membership、Userの複合境界へ固定する。
- 関連URLは本人所有の`ACTIVE MEMBER`リンクだけを許可する。
- URLが停止・期限切れになった商品は一覧へ返さず、過去の商品情報から停止URLを再利用できないようにする。
- 商品プロフィールの作成・更新を既存の外部URL監査ログへ記録する。
- URL本文は既存のExternal Tracking Linkを正本とし、商品プロフィールへ重複保存しない。

## 検証

- Prisma schemaとmigrationの対応
- Membership複合外部キーと所有境界
- Applicationでの入力正規化とfail-closed
- Web APIでの本人・サービス境界
- 保存済み商品の選択、復元、投稿文作成
- lint、typecheck、test、production build
