# 先行利用前の隔離環境での占い検証

Phase 2のPR-4が統合された `main` の `11cf516a` を基点とする。テスト用アカウントで実際のGoTrueが発行したセッションを使い、Next.jsの本人確認、API、隔離PostgreSQLを通して確認する。アプリ側の認証経路には手を加えていない。

## 実行方法

作業用のクリーンなworktreeで、既存の依存パッケージ、Dockerと、隔離認証の既存手順で利用しているローカルイメージ（`postgres:16`、`node:24-alpine`、`public.ecr.aws/supabase/gotrue:v2.192.0`）、E2E用Chromiumを使う。Windows PowerShellから実行する。

```powershell
pwsh -File scripts/test/fortune-isolated/run.ps1
```

新しい識別子を付けた使い捨て環境を既存スクリプトで作成し、マイグレーションを適用してテストを実行する。アプリ・認証・DBはループバックのみを使用する。実行後は、このテストのラベルが付いたコンテナとネットワークを停止・削除する。

## 検証範囲

- 390×844のブラウザで、限定Serviceへの一回限りの招待発行、招待リンクからのログイン復帰、参加同意、合成の利用規約・プライバシーポリシーへの同意、占いの年齢確認画面への到達を確認する。
- 同じブラウザ設定で、未ログイン時の認証画面、認証済み参加者の18歳確認、初回質問のスキップ、標準鑑定と提案、再読込後の結果維持を確認する。
- 実APIとDBで、年齢未確認の拒否、AI失敗時の標準鑑定、日次の再抽選防止、同じServiceの別参加者と別Serviceとの鑑定分離を確認する。
- 合成の鑑定を使い、任意評価の保存・取消し、追加質問の送信上限と再送、翌日相当の振り返り、同意撤回後の追加質問本文の消去、鑑定削除を確認する。追加質問のAI応答は生成先が利用できないケースを使用する。
