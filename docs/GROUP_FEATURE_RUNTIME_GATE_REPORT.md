# グループ機能 実行時チェック実装報告

## 目的

管理画面で設定したグループ機能の停止、利用期間、1日・1か月の上限を、実際の処理でも必ず守らせる。

## 今回接続した処理

グループの商品・企画を使う「今日の投稿案」生成時に、次の機能をサーバー側で確認する。

- SNS
- グループ企画
- 公式商品パック
- 外部成果計測URL（専用URLを使う場合）

親機能または必要な子機能が未設定、停止中、期間外、上限到達の場合は生成を開始しない。グループを使わない一般の投稿生成には影響させない。

## 利用回数

- Workspace、Group、参加者、機能を分離して保存する。
- 同じ操作Keyの再送は1回として数える。
- 判定と記録を同じDB transactionで行い、同時実行による上限超過を防ぐ。
- 外部処理の無制限な再試行を防ぐため、Gateを通過した実行試行を利用回数とする。
- 生成成功、採用、コピー、投稿は利用回数と混ぜず、既存の履歴で別に扱う。

## 管理画面

システム管理者は機能ごとに今日・今月の回数と、現在利用可能か、停止中か、開始前か、期限切れか、上限到達かを確認できる。グループ管理者は参加者ごとの割当画面で今日・今月の利用回数を確認できる。

## 今後の接続

画像生成Provider、BLOG、LINEなどを実装するときは、外部APIや高コスト処理を呼ぶ直前に同じ共通Gateを使用する。機能ごとに別の上限判定を作らない。
