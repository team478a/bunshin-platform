# 写真動画・AIナレーション実装報告

## 調査した内容

- 標準動画は字幕と単色背景だけを合成し、保存済み写真を選択・検証・RenderScriptへ渡す経路がなかった。
- 動画企画のナレーション文は保存済みだったが、音声生成、音声保存、合成、利用量記録、期限切れ削除が接続されていなかった。
- 動画レンダーJobには既存の冪等実行、短期署名URL、Creatomate合成、失敗再試行の境界があるため、この経路を拡張した。

## 変更内容

- 動画作成画面で、本人所有の利用可能な画像・ロゴを5枚まで順番付きで選べるようにした。
- 写真スライド動画を有効にし、企画生成後の各場面を選択写真へ安全に割り当てるようにした。
- AIナレーションを明示的なチェック項目として追加した。場面ごとの日本語台本をOpenAI音声APIでPCM化し、場面位置に合わせた30秒または60秒のWAVへ構成する。
- CreatomateのRenderScriptへ写真・字幕・音声を渡し、AI音声表示を動画内へ追加した。
- レンダー単位の音声処理台帳とmigrationを追加し、モデル、Prompt Version、声、試行回数、文字数、推定原価、処理時間、成否を記録する。
- 期限切れ処理と退会処理へ音声ファイルを追加した。

## 主要な設計判断

- 写真は企画へ外部URLを保存せず、所有権を確認したAsset IDだけを保存する。レンダー開始時に短期署名URLへ変換する。
- 写真の認可は作成時、レンダー投入時、実行時に再確認する。別利用者、別Workspace、失効、期限切れ、不正な保存パスは閉じて失敗させる。
- 音声は利用者が有効化した企画だけで生成する。台本は1秒あたり3文字以内を企画保存時にも検証し、長すぎる入力をAPI呼び出し前に拒否する。
- 429、5xx、通信障害は最大3回まで再試行し、4xxと入力不備は再試行しない。同じレンダーの同時生成はDB状態で排除する。
- 音声は90日で削除対象とし、利用者の退会時にもStorage削除後に台帳を削除済みへ更新する。
