# 商品・本人写真を使う画像生成

## 対象と実装

グループの画像作成画面で、利用者が商品・本人写真を1枚選択し、その生成依頼に限りOpenAI画像編集APIへ渡す。既存モデル・キー・生成枠・文字合成・完成画像確認の経路を再利用する。写真未選択時は既存の画像生成APIを使用する。

- JPEG/PNG/WebP、3MB以下、静止画1枚。入力本文をストリームで制限し、実際にデコードして画像形式と画素数を確認する。
- 向きを補正して最大1536pxに縮小し、EXIF等のメタデータを除いたPNGに変換する。
- 写真利用権、写っている本人の同意、OpenAIへの送信への確認を必須にする。ファイル名・元写真・EXIFはDBに保存しない。
- 既存の画像生成認可後に依頼を作成し、Workspace/Group/Owner/Requestごとの非公開Storageへ保存する。生のURL・Storageパス・別依頼の素材IDを入力として受け付けない。
- 正規化した写真のSHA-256と利用確認を依頼へ固定する。同じ受付キーを使って別ユーザー・Bunshin・Mission・写真に差し替える操作は拒否する。
- ジョブは保存写真のハッシュを検証してからAPIへ渡す。写真が失われた場合に写真なしの画像を勝手に生成しない。
- 参考写真専用Prompt VersionをAI使用量へ記録する。料金設定は既存の管理者固定原価設定を維持するため、参考画像の入力を含む実原価との差は運用上の調整が必要。
- 依頼作成から7日経過した参考写真を既存の期限切れ素材削除ジョブで順次削除する。削除失敗は再試行可能な状態に残す。期限後の同じ依頼への再アップロードを拒否する。完成画像の保存期間は既存どおり。

## DB変更

`20260907143000_social_image_reference`で画像生成依頼へ任意の`reference_image`と`reference_purged_at`を追加する。既存依頼はNULLのため動作を維持する。アプリ反映前にmigrationを適用する。

## 検証

写真なしのAPI呼出し、写真ありのmultipart送信、サイズ・形式拒否、EXIF除去、保存ハッシュ検証、所有範囲別パス、受付キーによる別Bunshin等への混入防止、期限削除と失敗再試行を自動検証する。実際のOpenAI呼出しと本番設定変更は行わない。

## 残作業と本番確認

既存キーを再利用する方針は利用者が承認済み。migrationとCI成功後、限定アカウントでアップロード→生成→文字合成→採用・保存、および削除ジョブの稼働を確認する。

毎日の自動生成に写真を継続利用する設定、素材ライブラリからの選択、複数写真、運営者の共通商品写真配布は対象外。生成結果の本人の外見や商品ラベルの完全再現は保証せず、採用前の確認を維持する。
